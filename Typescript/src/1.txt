
# TypeScript বেসিকস: ইনস্টলেশন, কম্পাইলেশন এবং টাইপ সিস্টেম নির্দেশিকা

## পরিচয় ও শিক্ষার উদ্দেশ্য

ভেবে দেখেছেন কি, কেন বড় প্রজেক্টে রানটাইমে সামান্য একটি টাইপ ভুল বা অমিলের কারণে পুরো অ্যাপ্লিকেশন ক্র্যাশ করে? JavaScript-এর এই অতিরিক্ত নমনীয়তা কীভাবে জটিল অ্যাপ্লিকেশন তৈরিতে বাধা হয়ে দাঁড়ায়, আর কীভাবে TypeScript আপনাকে কোড লেখার সময়ই ভুলগুলো ধরে বাগ-মুক্ত অ্যাপ্লিকেশন বানাতে সাহায্য করে?

এই ক্লাসের মূল শিক্ষার উদ্দেশ্যগুলো নিচে দেওয়া হলো:

* TypeScript কী এবং কেন এটি JavaScript-এর একটি সুপারসেট (Superset) তা ব্যাখ্যা করতে পারা।
* পিসিতে TypeScript ইনস্টল করা এবং প্রজেক্টের জন্য `tsconfig.json` কনফিগার করা।
* TypeScript কোডকে JavaScript-এ কম্পাইল (`tsc`) করা এবং `--watch` মোড ব্যবহার করা।
* Type Inference, Explicit Types, Union Types এবং `any` টাইপের ব্যবহার ও পার্থক্য বুঝতে পারা।
* প্রজেক্ট স্ট্রাকচারে `rootDir` ও `outDir`\-এর ভূমিকা প্রয়োগ করা।

## এই ক্লাসে কী শেখানো হয়েছে?

এই পাঠে TypeScript-এর একদম শুরু থেকে শুরু করে এর মৌলিক টাইপ সিস্টেম পর্যন্ত বিস্তারিত আলোচনা করা হয়েছে। নিচে শেখানো মূল বিষয়গুলোর তালিকা দেওয়া হলো:

1. **TypeScript-এর পরিচয় ও প্রয়োজনীয়তা:** JavaScript-এর সীমাবদ্ধতা এবং TypeScript কীভাবে স্ট্যাটিক টাইপ চেকিং প্রদান করে।
2. **ইনস্টলেশন ও এনভায়রনমেন্ট সেটআপ:** Node Package Manager (npm)-এর মাধ্যমে গ্লোবালি TypeScript ইনস্টল করা।
3. **কম্পাইলেশন এবং Workflow:** `tsc` কমান্ডের মাধ্যমে `.ts` ফাইলকে `.js` ফাইলে রূপান্তর করা, `tsconfig.json` ফাইল তৈরি ও কনফিগার করা (`rootDir` এবং `outDir` সেট করা) এবং অটোমেটিক রি-কম্পাইলেশনের জন্য `--watch` মোড চালু করা।
4. **Type Basics (Implicit Type Inference):** ভ্যারিয়েবল, ফাংশন, অ্যারেই এবং অবজেক্টের ক্ষেত্রে টাইপস্ক্রিপ্ট কীভাবে স্বয়ংক্রিয়ভাবে টাইপ অনুমান করে।
5. **Explicit Types &amp; Union Types:** সরাসরি টাইপ ডিক্লেয়ার করা এবং একটি ভ্যারিয়েবলে একাধিক টাইপ ব্যবহারের জন্য Union Type (`|`) ব্যবহার।
6. **Dynamic Type (** **any** **):** `any` টাইপ কী, এটি কীভাবে টাইপ চেকিং বন্ধ করে দেয় এবং কেন এর ব্যবহারে সতর্ক থাকা উচিত।

### TypeScript ফান্ডামেন্টালস মাইন্ড ম্যাপ

TypeScript-এর পরিবেশ সেটআপ, কম্পাইলেশন প্রসেস এবং টাইপ সিস্টেমের প্রধান শাখা-প্রশাখার একটি ভিজ্যুয়াল মাইন্ড ম্যাপ।

## TypeScript-এর পরিচিতি, পরিবেশ স্থাপন এবং কম্পাইলেশন প্রসেস

### ক. সহজ পরিচয়: TypeScript কী?

TypeScript হলো Microsoft দ্বারা তৈরি একটি প্রোগ্রামিং ল্যাঙ্গুয়েজ, যাকে JavaScript-এর **সুপারসেট (Superset)** বলা হয়। সুপারসেট কথার অর্থ হলো—JavaScript-এ যা কিছু আছে, TypeScript-এ তা সম্পূর্ণ বিদ্যমান, এবং তার সাথে অতিরিক্ত কিছু দরকারী ফিচার (প্রধানত **Static Type System**) যুক্ত করা হয়েছে।

### খ. কেন প্রয়োজন? (কোন সমস্যা সমাধান করে?)

JavaScript একটি **Dynamically Typed** ল্যাঙ্গুয়েজ। অর্থাৎ JavaScript-এ কোনো ভ্যারিয়েবলে যে কোনো সময় সংখ্যা, লেখা (string), বা অবজেক্ট রাখা যায়। এটি ছোট স্ক্রিপ্টের জন্য সুবিধাজনক হলেও বড় Enterprise Level অ্যাপ্লিকেশনে বড় সমস্যা তৈরি করে:

* ভুল টাইপ অ্যাসাইন করলেও JavaScript কোড লেখার সময় কোনো এরর দেখায় না, কিন্তু অ্যাপ চালু হলে রানটাইমে ক্র্যাশ করে।
* কোড এডিটরে ভালো **Intellisense** বা অটোকমপ্লিট সাজেশন পাওয়া যায় না।

TypeScript এই সমস্যা সমাধান করে। এটি কোড লেখার সময়ই (Compile-time) টাইপ চেক করে এবং ভুল ধরিয়ে দেয়।

### গ. কীভাবে কাজ করে? (Transpilation Process)

মনে রাখা জরুরি: **কোনো ব্রাউজার বা Node.js সরাসরি TypeScript কোড বুঝতে পারে না।** ব্রাউজার কেবল JavaScript বোঝে। তাই TypeScript কম্পাইলার (`tsc`) আমাদের লেখা `.ts` কোডকে বিশ্লেষণ করে বিশুদ্ধ `.js` ফাইলে রূপান্তর (Transpile) করে দেয়। কোডে কোনো টাইপ এরর থাকলে კომპাইলার সেখানেই কম্পাইলেশন আটকে দেয়।

### ঘ. বাস্তব উদাহরণ ও ইনস্টলেশন

একটি বাস্তব উদাহরণ ধরা যাক: আপনি একটি ফর্ম বানিয়েছেন যেখানে বয়স (Age) ইনপুট দিতে হবে। JavaScript-এ ভুলে যদি কেউ লেখার ফর্মে ইনপুট দেয়, তবে তা প্রসেস হওয়ার পর ভুল আউটপুট আসবে। কিন্তু TypeScript কোড কম্পাইল হওয়ার আগেই ডেভেলপারকে আটকে দেবে।

**ইনস্টলেশন কমান্ড:** টার্মিনালে গ্লোবালি ইনস্টল করতে লিখুন:

```
npm install -g typescript

```

ইনস্টলেশন যাচাই করতে `tsc -v` পরীক্ষা করা হয়।

### ঙ. প্রজেক্ট কনফিগারেশন (`tsconfig.json`), `rootDir` এবং `outDir`

একটি পেশাদার প্রজেক্টে সব টাইপস্ক্রিপ্ট ফাইল একটি ফোল্ডারে (যেমন `src`) রাখা হয় এবং তৈরি হওয়া JavaScript ফাইল অন্য ফোল্ডারে (যেমন `output` বা `dist`) আউটপুট করা হয়।

১. **কনফিগারেশন ফাইল তৈরি:**

```
tsc --init

```

এটি প্রজেক্টের রুট ডিরেক্টরিতে একটি `tsconfig.json` ফাইল তৈরি করে।

২. **tsconfig.json** **ফাইলের গুরুত্বপূর্ণ দুটি প্রপার্টি:**

* `rootDir`: যেখানে আমাদের টাইপস্ক্রিপ্ট সোর্স ফাইলসমূহ থাকে (যেমন: `"./src"`)।
* `outDir`: কম্পাইলড JavaScript ফাইলগুলো যেখানে জমা হবে (যেমন: `"./output"`)।

৩. **অটোমেটিক কম্পাইলেশন (Watch Mode):** বারবার `tsc` কমান্ড না লিখে ওয়াচ মোড চালু রাখলে ফাইল সেভ হওয়ার সাথে সাথে অটোমেটিক কম্পাইল হয়ে যায়:

```
tsc -w
# অথবা
tsc --watch

```

## TypeScript Type System: Type Inference, Explicit Types &amp; Union Types

### ক. Implicit Type Inference (স্বয়ংক্রিয় টাইপ অনুমান)

TypeScript অত্যন্ত বুদ্ধিমান। আপনি যদি কোনো ভ্যারিয়েবল ডিক্লেয়ার করার সময় টাইপ বলে নাও দেন, তবুও মান (value) দেখে এটি নিজে থেকেই টাইপ ঠিক করে নেয়। একে **Type Inference** বলা হয়।

```
let playerName = "Mashrafe"; // TypeScript বুঝে নিয়েছে এটি string
// playerName = 34; // ERROR: Type 'number' is not assignable to type 'string'.

```

এখানে `playerName`\-এ পরবর্তীতে সংখ্যা বসাতে চাইলে টাইপস্ক্রিপ্ট কম্পাইল টাইমে লাল দাগ দিয়ে এরর দেখাবে।

### খ. Explicit Types (স্পষ্টভাবে টাইপ নির্ধারণ)

যখন আপনি চান যে একটি ভ্যারিয়েবল শুরুতে খালি থাকবে বা নির্দিষ্ট টাইপ ছাড়া অন্য কিছু গ্রহণ করবে না, তখন সরাসরি টাইপ লিখে দিতে হয়। একে **Explicit Type** বলে।

**১. সাধারণ ভ্যারিয়েবল:**

```
let title: string;
let age: number;
let isCaptain: boolean;

title = "Captain";
age = 36;

```

**২. অ্যারেই (Array):**

```
let players: string[] = []; // শুধুমাত্র string রাখা যাবে
players.push("Sakib");
// players.push(75); // ERROR

```

**৩. অবজেক্ট (Object):**

```
let person: {
    name: string;
    age: number;
    isAdult: boolean;
};

person = {
    name: "Tamim",
    age: 34,
    isAdult: true
};

```

অবজেক্টে কোনো প্রপার্টি মিসিং থাকলে বা নতুন অচেনা প্রপার্টি যোগ করলে TypeScript এরর দেবে।

### গ. Union Types (একাধিক টাইপ অনুমোদন)

বাস্তব অ্যাপ্লিকেশনে অনেক সময় একটি ভ্যারিয়েবল বা অ্যারেইতে একাধিক টাইপের ডাটা থাকার প্রয়োজন হয়। এর জন্য **Pipe Operator (** **|** **)** ব্যবহার করে **Union Type** ডিক্লেয়ার করা হয়।

```
// Variable-এ Union Type
let id: string | number;
id = "USER-101"; // Valid
id = 101;        // Valid

// Array-তে Union Type
let mixed: (string | number)[] = [];
mixed.push("Tamim");
mixed.push(28);
// mixed.push(true); // ERROR: boolean অনুমোদিত নয়

```

### ঘ. Dynamic Type (`any`)

TypeScript-এ `any` নামে একটি বিশেষ টাইপ আছে। কোনো ভ্যারিয়েবলের টাইপ `any` দিলে টাইপস্ক্রিপ্ট সেখানে সব ধরনের টাইপ চেকিং বন্ধ করে দেয়।

```
let data: any;
data = "Sumit";
data = 45;
data = true;

```

&gt; **সতর্কতা (Warning):** `any` ব্যবহার করলে টাইপস্ক্রিপ্ট ব্যবহারের মূল উদ্দেশ্যই নষ্ট হয়ে যায়। এটি কোডকে পুনরায় অনিরাপদ JavaScript-এর মতো বানিয়ে ফেলে। তাই খুব বাধ্য না হলে `any` এড়িয়ে চলা উচিত।

## গুরুত্বপূর্ণ Command, Syntax ও সাধারণ ভুল

### ১. গুরুত্বপূর্ণ CLI Commands ও Options

* `npm install -g typescript`: গ্লোবালি TypeScript ইনস্টল করার জন্য।
* `tsc <filename.ts> * : একক কোনো ফাইলকে কম্পাইল করার জন্য।
* `tsc --init`: প্রজেক্টের কনফিগারেশন ফাইল `tsconfig.json` তৈরি করতে।
* `tsc` (ফাইল নেম ছাড়া): পুরো প্রজেক্টের `tsconfig.json` অনুযায়ী কম্পাইল করার জন্য।
* `tsc -w` বা `tsc --watch`: সোর্স ফাইলের পরিবর্তন পর্যবেক্ষণ করে স্বয়ংক্রিয়ভাবে কম্পাইল করতে।

### ২. Important Conceptual Differences

| বিষয়             | JavaScript                             | TypeScript                                           |
| ----------------- | -------------------------------------- | ---------------------------------------------------- |
| **Type Checking** | Dynamically Typed (রানটাইমে চেক হয়)   | Statically Typed (কম্পাইল টাইমে চেক হয়)             |
| **Execution**     | ব্রাউজার ও Node.js সরাসরি চালাতে পারে  | ব্রাউজার সরাসরি চালাতে পারে না, JS-এ অনুবাদ করতে হয় |
| **Errors**        | অ্যাপ চালুর পর ভুলের কারণে ক্র্যাশ করে | কোড লেখার সময়ই ভুল এডিটরে ধরা পড়ে                  |
| **Intellisense**  | সীমিত                                  | অসাধারণ অটোকমপ্লিট ও রেফারেন্স সাজেশন                |

### ৩. Beginner-দের সাধারণ ভুল (Common Mistakes) ও সমাধান

১. **ব্রাউজারে সরাসরি** **.ts** **ফাইল লিংক করা:**

* *ভুল:* HTML ফাইলে `` ব্যবহার করা।
* *সমাধান:* এইচটিএমএল ফাইলে সবসময় কম্পাইল হওয়া JavaScript ফাইল যুক্ত করবেন, যেমন ``।

২. **ফাংশন প্যারামিটারে টাইপ না দেওয়া:**

* *ভুল:* `function multiply(a, b) { return a * b; }` (এখানে a ও b-এর টাইপ `any` হয়ে যায়)।
* *সমাধান:* স্পষ্টভাবে টাইপ বলে দেওয়া `function multiply(a: number, b: number): number { return a * b; }`

৩. **অবজেক্টে নতুন প্রপার্টি যোগ করার চেষ্টা করা:**

* *ভুল:* ডিক্লেয়ার করার বাইরে নতুন কোনো প্রপার্টি অবজেক্টে বসানো।
* *সমাধান:* অবজেক্ট ডিক্লেয়ার করার সময়ই প্রয়োজনীয় প্রপার্টি নির্ধারণ করতে হবে অথবা টাইপ ডিফাইন করে নিতে হবে।

### TypeScript-এ শিক্ষানবিসদের সাধারণ ভুলসমূহ

TypeScript শেখার শুরুতে শিক্ষানবিসরা যেসব সাধারণ ভুল করে এবং সেগুলো কীভাবে সমাধান করবে তার অডিও আলোচনা।

## সংক্ষেপ ও মূল মূল্যায়ন

### সংক্ষেপ (Synthesis)

TypeScript কোনো নতুন প্রোগ্রামিং ভাষা নয়, এটি JavaScript-এর ওপর তৈরি একটি শক্তিশালী টাইপ চেকিং লেয়ার। এটি কোড ডেব্রিফিং, টিমে কাজ করা এবং বড় প্রজেক্টে রানটাইম বাগ দূর করতে অত্যন্ত কার্যকর।

### মূল শিক্ষা (Key Takeaways)

* TypeScript হলো JavaScript-এর সুপারসেট, যা কোড কম্পাইল টাইমে চেক করে।
* ব্রাউজারে চালানের আগে `tsc` কমান্ড দিয়ে `.ts` ফাইলকে `.js` ফাইলে রূপান্তর করতে হয়।
* `tsconfig.json` ফাইলের মাধ্যমে `rootDir` এবং `outDir` সেট করে প্রজেক্ট গুছিয়ে রাখা যায়।
* Type Inference স্বয়ংক্রিয়ভাবে টাইপ অনুমান করে, তবে প্রয়োজনে Explicit Typing ও Union Typing (`|`) ব্যবহার করা ভালো।
* `any` টাইপ টাইপস্ক্রিপ্টের সুরক্ষা নষ্ট করে, তাই এটি ব্যবহারে সচেতন হতে হবে।
