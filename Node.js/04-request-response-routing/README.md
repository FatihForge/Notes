## Introduction

আপনি কি জানেন যে Node.js মাত্র একটি সিঙ্গেল থ্রেড (Single Thread) ব্যবহার করে কীভাবে লাখ লাখ ইউজারের রিকোয়েস্ট একসাথে হ্যান্ডেল করে? যেখানে অন্যান্য প্রযুক্তির একাধিক থ্রেডের প্রয়োজন হয়, সেখানে Node.js একাই একটি সুপার-ম্যানেজারের মতো পুরো সিস্টেম সামলায়! এই লেসনে আমরা Node.js-এর এই জাদুকরী আর্কিটেকচার এবং কীভাবে ক্লায়েন্টের রিকোয়েস্ট প্রসেস করে রেসপন্স ও রিডাইরেকশন হ্যান্ডেল করতে হয় তা বিস্তারিত শিখব।

**শিক্ষণীয় উদ্দেশ্যসমূহ:**

* Node.js-এর সিঙ্গেল-থ্রেডেড আর্কিটেকচার এবং Event Loop-এর কাজের প্রক্রিয়া গভীরভাবে বোঝা।
* Request Object-এর গুরুত্বপূর্ণ অংশসমূহ (URL, Method, Headers) বিশ্লেষণ করা।
* ক্লায়েন্টের জন্য কাস্টম HTML Response তৈরি করা এবং তা পাঠানো।
* কাস্টম Routing তৈরি করা এবং ইউজার ইনপুট নিয়ে তা ফাইলে সংরক্ষণ করা।
* রিকোয়েস্ট রিডাইরেকশন (Redirection) এবং Status Code-এর সঠিক ব্যবহার শেখা।

## এই ক্লাসে কী কী শেখানো হয়েছে?

আমরা গত ক্লাসে একটি বেসিক ওয়েব সার্ভার তৈরি করেছিলাম। এই ক্লাসে আমরা সেই সার্ভারকে আরও ডাইনামিক এবং কার্যকর করে তোলার উপায় শিখব। ক্লাসের মূল বিষয়গুলো নিচে দেওয়া হলো:

* **Node.js-এর জীবনচক্র:** কীভাবে Node.js ব্যাকগ্রাউন্ডে কাজ চালায় এবং এর ইন্টারনাল আর্কিটেকচার কীভাবে কাজ করে।
* **Event Loop এবং Thread Pool:** সিঙ্গেল-থ্রেডেড হওয়া সত্ত্বেও কীভাবে মাল্টি-টাস্কিং করা সম্ভব হয়।
* **process.exit() এর ব্যবহার:** চলমান সার্ভার প্রসেসকে কখন এবং কীভাবে বন্ধ করতে হয়।
* **Request এবং Response অবজেক্ট:** ক্লায়েন্টের পাঠানো ডেটা বিশ্লেষণ করা এবং ক্লায়েন্টকে কাস্টম ডেটা ফেরত পাঠানো।
* **Routing:** আলাদা আলাদা URL-এর জন্য আলাদা রেসপন্স তৈরি করা।
* **HTML Form ও POST Request:** ইউজার থেকে ইনপুট নেওয়া এবং তা সার্ভারে হ্যান্ডেল করা।
* **Redirection:** ইউজারকে এক পেজ থেকে অন্য পেজে রিডাইরেক্ট করা এবং ফাইল সিস্টেমে ডেটা রাইট করা।

## Node.js Architecture এবং Event Loop

**What is it:** Node.js হলো একটি Single-Threaded রানটাইম এনভায়রনমেন্ট। এর অর্থ হলো এটি একই সময়ে রান করার জন্য কেবল একটিমাত্র মেইন থ্রেড (Thread) ব্যবহার করে। তবে ভারী কাজগুলো ব্যাকগ্রাউন্ডে করার জন্য এটি Event Loop এবং Thread Pool ব্যবহার করে।

**Why is it used:** মাল্টি-থ্রেডেড সিস্টেমে প্রতি ইউজারের জন্য আলাদা থ্রেড তৈরি করতে অনেক মেমোরি খরচ হয়। Node.js অত্যন্ত হালকা (Lightweight) এবং এটি কম মেমোরি খরচ করে একটি মাত্র থ্রেড দিয়েই লাখ লাখ ইউজারের রিকোয়েস্ট একই সাথে হ্যান্ডেল করতে পারে।

**How does it work:**

1. যখনই কোনো রিকোয়েস্ট আসে, সেটি সরাসরি একটি Event Queue-তে জমা হয়।
2. Event Loop অবিরত চলতে থাকে এবং এই কিউ (Queue) থেকে একটি করে রিকোয়েস্ট নিয়ে প্রসেস করে।
3. যদি কোনো কাজে বেশি সময় লাগে (যেমন: Database থেকে ডেটা আনা বা File Read/Write করা), তখন Event Loop নিজে সেই কাজের জন্য অপেক্ষা করে বসে থাকে না। সে কাজটিকে ব্যাকগ্রাউন্ডে থাকা Thread Pool-এর একটি Worker Thread-এর কাছে পাঠিয়ে দেয়।
4. Worker Thread কাজ শেষ করার পর একটি Callback Function-এর মাধ্যমে Event Loop-কে জানায়।
5. Event Loop তখন সেই কাস্টমার বা ক্লায়েন্টকে ফাইনাল রেসপন্স পাঠিয়ে দেয়।

**Mental Model:** একে একটি ব্যস্ত অফিসের ম্যানেজারের মতো চিন্তা করুন। ম্যানেজার নিজে ফাইল লেখার কাজ বা চা বানানোর কাজ করেন না। যখনই কোনো ক্লায়েন্ট আসে, তিনি রিকোয়েস্টটি শুনে সহকারীকে (Worker Thread) কাজ বুঝিয়ে দেন এবং নিজে পরবর্তী ক্লায়েন্টের সাথে কথা বলা শুরু করেন। কাজ শেষ হলে সহকারী ম্যানেজারকে ফাইলটি দেয় এবং ম্যানেজার ক্লায়েন্টকে তা বুঝিয়ে দেন।

### 📊 Node.js Event Loop ও Thread Pool আর্কিটেকচার ডায়াগ্রাম
```text
  +-------------------------------------------------------------+
  |                   Incoming Client Requests                  |
  +-------------------------------------------------------------+
                                │
                                ▼
  +-------------------------------------------------------------+
  |                        Event Queue                          |
  +-------------------------------------------------------------+
                                │
                                ▼
  +-------------------------------------------------------------+
  |                Single Main Thread (Event Loop)              |
  +-------------------------------------------------------------+
               │                                │
    (Fast / Sync Operations)        (Heavy / Blocking I/O Tasks)
               │                                │
               ▼                                ▼
       Immediate Response          ┌─────────────────────────┐
                                   │    libuv Thread Pool    │
                                   │ (Worker Threads 1,2,3,4)│
                                   └────────────┬────────────┘
                                                │ (Callback)
                                                ▼
                                   ┌─────────────────────────┐
                                   │     Callback Queue      │
                                   └─────────────────────────┘
```

## process.exit() এর মাধ্যমে Event Loop থেকে প্রস্থান

**What is it:** `process.exit()` হলো Node.js-এর একটি গ্লোবাল প্রসেস মেথড, যা চলমান Node.js অ্যাপ্লিকেশন বা এর লিসেনিং লুপ (Event Loop) সরাসরি বন্ধ করে দেয়।

**Why is it used:** সার্ভার সাধারণত চিরকাল চলতে থাকার জন্য তৈরি করা হয় যাতে যেকোনো সময় ক্লায়েন্ট রিকোয়েস্ট পাঠাতে পারে। তবে ডেভলপমেন্টের সময় কোনো বড় এরর হলে বা নির্দিষ্ট কোনো টেস্ট কন্ডিশন পূরণ হলে সার্ভারকে বন্ধ করার প্রয়োজন হতে পারে।

**How does it work:** কোডে যখনই এই ফাংশনটি কল করা হয়, Node.js সাথে সাথে তার লিসেনিং প্রসেসটি কিল (Kill) বা বন্ধ করে দেয় এবং টার্মিনালে ফেরত আসে। এর পর ক্লায়েন্ট আর সার্ভারে অ্যাক্সেস করতে পারে না।

**Common Mistakes:** সাধারণ রিকোয়েস্ট হ্যান্ডলিং কোডে ভুলবশত এটি ব্যবহার করলে প্রথম রিকোয়েস্ট আসার পরেই সার্ভার বন্ধ হয়ে যাবে, যা রিয়েল-ওয়ার্ল্ড অ্যাপ্লিকেশনে বড় ধরনের বিপর্যয় ডেকে আনতে পারে। তাই এটি অত্যন্ত সতর্কতার সাথে ব্যবহার করতে হবে।

## Request Object এবং এর অভ্যন্তরীণ বিষয়সমূহ

**What is it:** ক্লায়েন্ট যখন সার্ভারে কোনো রিকোয়েস্ট পাঠায়, তখন Node.js স্বয়ংক্রিয়ভাবে একটি Request Object তৈরি করে। এতে ক্লায়েন্টের পাঠানো সমস্ত তথ্য জমা থাকে।

**Why is it used:** ইউজার মূলত কী চাচ্ছে, সেটির ওপর ভিত্তি করে সিদ্ধান্ত নেওয়ার জন্য এই অবজেক্টটি ব্যবহার করা হয়। যেমন: ইউজার কোন পেজে যেতে চায় বা সে কী ধরনের ডেটা পাঠিয়েছে।

**Important Properties:**

* **req.url:** এটি ইউজারের রিকোয়েস্ট করা পাথ নির্দেশ করে। যেমন ইউজার যদি `http://localhost:3001/products` ব্রাউজ করে, তবে `req.url` এর মান হবে `/products`।
* **req.method:** এটি রিকোয়েস্টের ধরন বা HTTP Method নির্দেশ করে (যেমন: GET বা POST)।
* **req.headers:** রিকোয়েস্টের সাথে পাঠানো অতিরিক্ত তথ্য বা মেটাডেটা (Metadata) যেমন: হোস্ট নেম, ব্রাউজার ইনফরমেশন, কুকি ইত্যাদি ধারণ করে।

**Mental Model:** এটি হলো একটি চিঠির মতো। চিঠির উপরে প্রাপকের ঠিকানা (`req.url`), চিঠির উদ্দেশ্য (`req.method`), এবং প্রেরকের খামের ওপরের লেবেল বা ডাকটিকিট (`req.headers`) থাকে।

## Response অবজেক্ট এবং ক্লায়েন্টে রেসপন্স পাঠানো

**What is it:** Response Object হলো সার্ভারের পক্ষ থেকে ক্লায়েন্টকে পাঠানো একটি উত্তরপত্র বা খালি ব্যাগ, যা পূরণ করে ব্রাউজারে পাঠানো হয়।

**Why is it used:** ব্রাউজারকে সঠিক কন্টেন্ট (যেমন HTML পেজ, JSON ডেটা বা সাধারণ টেক্সট) দেখানোর জন্য এবং রিকোয়েস্টটি যে সফল হয়েছে তা নিশ্চিত করতে এটি ব্যবহৃত হয়।

**Important Methods:**

* **res.setHeader('Content-Type', 'text/html'):** রেসপন্সের মেটাডেটা সেট করার জন্য ব্যবহৃত হয়। এখানে ব্রাউজারকে বলা হচ্ছে যে পাঠানো ডেটাটি একটি HTML ডকুমেন্ট।
* **res.write():** রেসপন্স বডিতে ডেটা বা HTML কোড লেখার জন্য ব্যবহৃত হয়। এটি একাধিকবার কল করা সম্ভব।
* **res.end():** রেসপন্স তৈরি করার প্রক্রিয়া সম্পন্ন করে এবং ব্রাউজারে ডেটা পাঠিয়ে দেয়। এটি অবশ্যই কল করতে হবে, অন্যথায় ব্রাউজার লোড হতেই থাকবে।

**Mental Model:** এটি রেস্তোরাঁর সার্ভিং প্লেটের মতো। প্লেটটি টেবিলে দেওয়ার আগে শেফ তাতে বিভিন্ন খাবার সাজান (`res.write()`), এবং সাজানো শেষ হলে কাস্টমারের সামনে পরিবেশন করেন (`res.end()`).

## Routing এবং মাল্টিপল রিকোয়েস্ট হ্যান্ডলিং

**What is it:** ইউজার কোন ইউআরএল (URL) রিকোয়েস্ট করছে তার ওপর ভিত্তি করে আলাদা আলাদা পেজ বা আউটপুট দেখানোর লজিক্যাল সিদ্ধান্ত নেওয়ার প্রক্রিয়াকে Routing বলা হয়।

**Why is it used:** একটি পূর্ণাঙ্গ ওয়েবসাইটে কেবল একটি পেজ থাকে না। হোমপেজ, প্রোডাক্ট পেজ, কন্টাক্ট পেজ ইত্যাদি আলাদা আলাদা পেজ দেখাতে রাউটিং অপরিহার্য।

**How does it work:** `req.url` এবং `req.method` এর ওপর ভিত্তি করে সাধারণ কন্ডিশনাল স্টেটমেন্ট (যেমন `if-else`) ব্যবহার করে এই রাউটিং করা হয়।

**Crucial Warning (Error Prevention):** `res.end()` কল করার পর কোড এক্সিকিউশন বন্ধ করতে অবশ্যই `return` ব্যবহার করতে হবে। যদি `return` না করা হয়, তবে কোডটি নিচের দিকে চলতে থাকবে এবং একই রেসপন্সে পুনরায় ডেটা লেখার চেষ্টা করবে। এর ফলে Node.js-এ **'Cannot set headers after they are sent to the client'** এররটি ঘটে।

## User Input এবং HTML Form সাবমিট করা

**What is it:** সার্ভার থেকে ইউজারকে একটি HTML Form পাঠানো হয়, যেখানে ইউজার তথ্য দিয়ে সাবমিট করতে পারে এবং সেই ডেটা পুনরায় সার্ভারে প্রসেস করার জন্য ফিরে আসে।

**Why is it used:** ইউজার রেজিস্ট্রেশন, সার্চ, লগইন বা যেকোনো ধরনের ইনপুট সার্ভারে গ্রহণ করার জন্য এটি ব্যবহার করা হয়।

**How does it work:**

1. সার্ভার প্রথমে হোমপেজে একটি HTML ফর্ম পাঠায়।
2. ফর্মে দুটি গুরুত্বপূর্ণ অ্যাট্রিবিউট থাকে: `action` এবং `method`।
  * **action="/submit-details":** নির্দেশ করে যে ফর্মটি সাবমিট হলে ডেটা কোন পাথে যাবে।
  * **method="POST":** নির্দেশ করে যে ডেটাটি বডির ভেতর দিয়ে সুরক্ষিতভাবে পাঠানো হবে।
3. ইনপুট ফিল্ডগুলোতে একটি `name` অ্যাট্রিবিউট থাকতে হবে (যেমন `name="username"`)। এই নাম ব্যবহার করেই সার্ভার পরে ডেটাটি খুঁজে পায়।

## Request Redirect করা এবং ফাইলে ডেটা লেখা

**What is it:** কোনো অ্যাকশন (যেমন ফর্ম সাবমিট) সম্পন্ন হওয়ার পর ইউজারকে অন্য একটি নির্দিষ্ট পেজে (যেমন হোমপেজে) স্বয়ংক্রিয়ভাবে পাঠিয়ে দেওয়াকে Redirection বলা হয়। একই সাথে ইউজার থেকে প্রাপ্ত ডেটা সার্ভারের লোকাল ফাইলে লিখে রাখা হয়।

**Why is it used:** ফর্ম সাবমিট করার পর ইউজারকে একই ফাঁকা পেজে বসিয়ে না রেখে সরাসরি মূল পেজে ফিরিয়ে নেওয়ার মাধ্যমে একটি চমৎকার ইউজার এক্সপেরিয়েন্স প্রদান করা যায়।

**How it works (Implementation Steps):**

1. **Status Code 302 Set করা:** `res.statusCode = 302;` এর মাধ্যমে ব্রাউজারকে বলা হয় যে পেজটি রিডাইরেক্ট করতে হবে।
2. **Location Header সেট করা:** `res.setHeader('Location', '/');` এর মাধ্যমে ব্রাউজারকে বলা হয় যে তাকে হোমপেজে (`/` পাথে) চলে যেতে হবে।
3. **ফাইল রাইট করা:** Node.js-এর বিল্ট-ইন `fs` (File System) মডিউলের `fs.writeFileSync()` মেথড ব্যবহার করে ডেটা ফাইলে লিখে রাখা হয়।
4. **রেসপন্স এন্ড করা:** `res.end()` কল করে রেসপন্সটি ক্লোজ করা হয়, এবং ব্রাউজার সাথে সাথে নতুন লোকেশনে চলে যায়।

## গুরুত্বপূর্ণ পার্থক্য এবং সাধারণ ভুলসমূহ

**GET বনাম POST রিকোয়েস্ট:**

* **GET:** সার্ভার থেকে কেবল ডেটা পড়ার বা রিট্রিভ করার জন্য ব্যবহৃত হয়। এর ডেটা ইউআরএল (URL)-এ দৃশ্যমান থাকে, তাই এটি সংবেদনশীল ডেটা পাঠানোর জন্য উপযুক্ত নয়।
* **POST:** সার্ভারে নতুন ডেটা পাঠানোর জন্য ব্যবহৃত হয়। এর ডেটা রিকোয়েস্ট বডির ভেতর থাকে, তাই এটি তুলনামূলকভাবে নিরাপদ এবং বড় ডেটা পাঠানোর জন্য ব্যবহৃত হয়।

**res.write() বনাম res.end():**

* **res.write():** এটি রেসপন্সে একাধিকবার ডেটা যোগ করতে পারে, কিন্তু রেসপন্সটি ব্রাউজারের কাছে পাঠায় না।
* **res.end():** এটি রেসপন্স তৈরির কাজ শেষ করে এবং ডেটা ব্রাউজারে ডেলিভারি দেয়। এর পর আর রেসপন্সে কিছু লেখা যায় না।

**সাধারণ ভুল ও প্রতিকার:**

* **সার্ভার রিস্টার্ট না করা:** কোডে যেকোনো পরিবর্তন করার পর টার্মিনালে `Ctrl + C` দিয়ে সার্ভার বন্ধ করে পুনরায় `node app.js` রান করতে হবে, অন্যথায় নতুন কোড কাজ করবে না।
* **রিটার্ন না করা:** কন্ডিশনাল রাউটিং লজিকে `res.end()` করার পর `return` না লিখলে কোড এক্সিকিউশন থামে না এবং এরর দেখা দেয়।

## Quick Revision এবং গুরুত্বপূর্ণ Terminology

**ঝটপট রিভিশন:**

* **Event Loop:** Node.js-এর হৃদপিণ্ড, যা সিঙ্গেল-থ্রেডেড হয়েও অ্যাসিনক্রোনাস কাজগুলো পরিচালনা করে।
* **Thread Pool:** ভারী কাজগুলো (যেমন ফাইল বা ডেটাবেস অপারেশন) ব্যাকগ্রাউন্ডে করার জন্য নিয়োজিত কর্মী দল।
* **process.exit():** কোড প্রসেস বন্ধ করার মেথড।
* **req.url &amp; req.method:** ইউজারের চাওয়া পাথ এবং মেথড চেক করার প্রপার্টি।
* **res.setHeader():** রেসপন্সের মেটাডেটা (যেমন কন্টেন্ট টাইপ বা লোকেশন) সেট করার পদ্ধতি।
* **Status Code 302:** সাময়িক রিডাইরেকশনের সিগন্যাল।

**গুরুত্বপূর্ণ Terminology:**

* **Single-Threaded:** একই সময়ে কেবল একটি কাজ প্রসেস করার ক্ষমতা।
* **Metadata:** ডেটা সম্পর্কিত অতিরিক্ত তথ্য (যা Headers-এ থাকে)।
* **Routing:** পাথের ওপর ভিত্তি করে সঠিক পেজে ক্লায়েন্টকে নিয়ে যাওয়া।
* **Redirection:** ইউজারকে স্বয়ংক্রিয়ভাবে এক ইউআরএল থেকে অন্য ইউআরএলে পাঠানো।

## Summary

এই লেসনে আমরা Node.js সার্ভারের রিকোয়েস্ট এবং রেসপন্স আর্কিটেকচার সম্পর্কে বিস্তারিত জেনেছি। আমরা দেখেছি কীভাবে সিঙ্গেল-থ্রেডেড হওয়া সত্ত্বেও Event Loop এবং Thread Pool-এর সমন্বয়ে Node.js অত্যন্ত দক্ষতার সাথে কাজ সম্পন্ন করে। এছাড়া কাস্টম রাউটিং, ফর্ম হ্যান্ডলিং, এবং ফাইল সিস্টেমে ডেটা রাইট করার সাথে সাথে রিডাইরেকশন প্রক্রিয়ার ব্যবহারিক জ্ঞান অর্জন করেছি। এই মূল কনসেপ্টগুলোই পরবর্তীতে এক্সপ্রেস (Express.js) ফ্রেমওয়ার্ক শেখার ভিত্তি স্থাপন করবে।
