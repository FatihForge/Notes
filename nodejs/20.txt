## ভূমিকা ও শিক্ষার উদ্দেশ্য

যেকোনো বাস্তবমুখী ব্যাকএন্ড অ্যাপ্লিকেশন—যেমন Facebook, Airbnb, বা Google Photos—ফাইল বা ছবি আপলোড করার সুবিধা ছাড়া একেবারে অসম্পূর্ণ। কিন্তু চিন্তার বিষয় হলো, সাধারণ টেক্সট ডাটার মতো কোনো বাইনারি ফাইলকে (যেমন একটি ১০ মেগাবাইটের ছবি বা পিডিএফ) কেন সরাসরি এইচটিএমএল ফর্মের মাধ্যমে পাঠানো যায় না? সার্ভারই বা কীভাবে এই ফাইলগুলোকে রিসিভ করে লোকাল স্টোরেজে সঠিক নামে সংরক্ষণ করে?

এই পাঠ শেষে আপনি যা যা শিখবেন এবং করতে পারবেন:

* HTML ফাইল পিকারের কাজ এবং `enctype="multipart/form-data"`\-এর প্রয়োজনীয়তা ব্যাখ্যা করতে পারবেন।
* Express-এ `multer` প্যাকেজ ব্যবহার করে ক্লায়েন্ট থেকে পাঠানো ফাইল রিসিভ করতে পারবেন।
* `multer.diskStorage` ব্যবহার করে ফাইলগুলোকে ইউনিক নাম দিয়ে ডিরেক্টরিতে সংরক্ষণ করতে পারবেন।
* ব্যাকএন্ড ও ফ্রন্টএন্ডে ফাইল ফিল্টারিং (যেমন শুধু JPG/PNG গ্রহণ করা) বাস্তবায়ন করতে পারবেন।
* `express.static` মিডলওয়্যার দিয়ে আপলোড করা ছবি ইউআই (UI)-তে প্রকাশ করতে পারবেন।
* ডাটা এডিটের সময় আগের ফাইল সুরক্ষিত রাখার ব্যাকএন্ড লজিক তৈরি করতে পারবেন।
* Node.js-এর `fs.unlink` দিয়ে অব্যবহৃত পুরানো ফাইল ডিলিট করা এবং `res.download` দিয়ে সিকিউর ডাউনলোড ফিচার তৈরি করতে পারবেন।

## এই ক্লাসে কী শেখানো হয়েছে এবং HTML File Picker ও Multipart Form Data

### ১. এই ক্লাসে কী শেখানো হয়েছে?

এই ক্লাসে ব্যাকএন্ড ডেভেলপমেন্টের একটি অত্যন্ত গুরুত্বপূর্ণ অংশ—**ফাইল আপলোড, প্রসেসিং, ডিস্ক সেভিং, স্ট্যাটিক সার্ভিসিং, এডিটিং এবং ফিজিক্যাল ডিলিট** করার পুরো লাইফসাইকেল শেখানো হয়েছে।

### ২. HTML File Picker (``)

ফাইল পিকার হলো এইচটিএমএল-এর একটি বিল্ট-ইন উপাদান, যার মাধ্যমে ব্যবহারকারী তার কম্পিউটার বা মোবাইল থেকে যেকোনো ফাইল সিলেক্ট করতে পারেন।

```

```

* **type="file"**: ব্রাউজারকে নির্দেশ করে একটি 'Choose File' বাটন তৈরি করতে।
* **accept**: ব্যবহারকারী কোন ধরণের ফাইল সিলেক্ট করতে পারবেন তা ক্লায়েন্ট সাইডে ফিল্টার করে। যেমন: `accept="image/*"` বা নির্দিষ্ট এক্সটেনশন `accept=".jpg, .png"`।
* **multiple**: এটি যুক্ত করলে ইউজার একসাথে একাধিক ফাইল সিলেক্ট করতে পারেন।

*সীমাবদ্ধতা:* ফ্রন্টএন্ডের এই ফিল্টার কেবল ইউজার এক্সপেরিয়েন্স (UX) উন্নত করার জন্য। কোনো চতুর ইউজার ব্রাউজারের Inspect Element দিয়ে এটি মুছে ফেলে যেকোনো ক্ষতিকর ফাইল পাঠাতে পারে। তাই ব্যাকএন্ডে ফাইল টাইপ যাচাই করা অপরিহার্য।

### ৩. `application/x-www-form-urlencoded` বনাম `multipart/form-data`

একজন ব্যাকএন্ড ডেভেলপমেন্ট শিখতে থাকা শিক্ষার্থীর সবচেয়ে বড় কনফিউশন ঘটে এখানে। সাধারণ ফর্মে ডাটা পাঠালে ফাইল সার্ভারে পৌঁছায় না কেন?

* **application/x-www-form-urlencoded** **(ডিফল্ট ধরন):** আমরা যখন ফর্মে কোনো টেক্সট ইনপুট (যেমন নাম, ইমেইল, পাসওয়ার্ড) পাঠাই, তখন ব্রাউজার সব টেক্সটকে একটি দীর্ঘ ইউআরএল এনকোডেড স্ট্রিং বানিয়ে পাঠায় (যেমন: `name=Mohan&amp;city=Dhaka`)। এটি শুধু প্লেইন টেক্সটের জন্য উপযোগী। কিন্তু যখন একটি বাইনারি ছবি পাঠানো হয়, তখন ডিফল্ট ফর্ম শুধুমাত্র ফাইলের নামটাই টেক্সট হিসেবে পাঠায় (`photo=my_pic.jpg`), আসল ছবির ডেটা পাঠায় না।
* **multipart/form-data** **(ফাইল আপলোডের জন্য প্রয়োজনীয়):** ছবি বা ভিডিও হলো বাইনারি ডেটা এবং এটি আকারে অনেক বড় হতে পারে। তাই এটিকে একবারে ইউআরএল এনকোড করে পাঠানো সম্ভব নয়। `enctype="multipart/form-data"` ব্যবহার করলে পুরো ফর্ম ডেটাটি ছোট ছোট ভাগে (Parts বা Chunks) বিভক্ত হয়ে সার্ভারে স্ট্রিমিং আকারে প্রেরিত হয়। সার্ভার প্রতিটি পার্ট আলাদা আলাদা রিসিভ করে টেক্সট ও বাইনারি ডাটা পৃথক করতে পারে।

> **মূল কনসেপ্ট সারসংক্ষেপ (Core Concept Breakdown):**
> HTML File Picker এবং ফর্মের বিভিন্ন enctype (urlencoded বনাম multipart) কীভাবে কাজ করে তার একটি স্ট্রাকচার্ড ভিজ্যুয়াল রূপরেখা।

## Node.js-এ Multer প্যাকেজ, ফাইল সেভ এবং Custom Naming Strategy

### ১. Multer প্যাকেজ কী এবং কেন প্রয়োজন?

Express.js বাই ডিফল্ট `multipart/form-data` ফর্ম বডি পার্স করতে পারে না (অর্থাৎ `req.body` খালি বা undefined দেখায়)। এই মাল্টিপার্ট ডাটা প্রসেস করার জন্য আমাদের **Multer** নামের একটি থার্ড-পার্টি npm প্যাকেজ ব্যবহার করতে হয়।

Multer একটি মিডলওয়্যার হিসেবে কাজ করে। এটি ইনকামিং বাইনারি চ্যাংকগুলোকে একত্রিত করে সার্ভারের ডিরেক্টরিতে সেভ করে এবং আমাদের সুবিধার্থে একটি `req.file` বা `req.files` অবজেক্ট তৈরি করে দেয়।

### ২. Multer সেটিং: `dest` বনাম `diskStorage`

**ক. সাধারণ পদ্ধতি (** **dest** **ব্যবহার):**

```
const multer = require('multer');
const upload = multer({ dest: 'uploads/' });

```

এটি লিখলে `uploads` নামের ফোল্ডারে ফাইল সেভ হবে, কিন্তু ফাইলের নাম হবে একটি অদ্ভুত র্যান্ডম হ্যাশ (যেমন: `e57b3a891f...`) এবং এতে কোনো এক্সটেনশন (`.jpg` বা `.png`) থাকবে না। ফলে উইন্ডোজ বা ম্যাক ব্রাউজার ফাইলটি ওপেন করতে পারে না।

**খ. কাস্টম ও প্রফেশনাল পদ্ধতি (** **multer.diskStorage** **):** ফাইলকে কাস্টম নাম ও এক্সটেনশনসহ সেভ করার জন্য আমরা `diskStorage` ব্যবহার করি।

```
const multer = require('multer');

// কাস্টম ফাইল নেমিং ও ডিরেক্টরি সেটআপ
const storage = multer.diskStorage({
  destination: (req, file, cb) =&gt; {
    // প্রথম প্যারামিটার Error (null), দ্বিতীয়টি ফোল্ডার পাথ
    cb(null, 'uploads/');
  },
  filename: (req, file, cb) =&gt; {
    // ইউনিক নাম তৈরি করা
    const uniquePrefix = Math.random().toString(36).substring(2, 10);
    const fileName = `${uniquePrefix}-${file.originalname}`;
    cb(null, fileName);
  }
});

const upload = multer({ storage: storage });

```

### ৩. ইউনিক নেমিং কেন দরকার?

ধরা যাক, দুজন ব্যবহারকারী আলাদা দুটি প্রোফাইল পিকচার আপলোড করলেন, কিন্তু দুজনেরই ছবির নাম `profile.jpg`। যদি আমরা সরাসরি আসল নাম ব্যবহার করি, তবে প্রথম ব্যবহারকারীর ছবিটির ওপর দ্বিতীয়জনের ছবি ওভাররাইট হয়ে যাবে!

এই ওভাররাইট সমস্যা সমাধান করতে আমরা অরিজিনাল নামের আগে একটি র্যান্ডম স্ট্রিং বা ইউনিক টাইমেস্ট্যাম্প যুক্ত করে দিই (যেমন: `a8f9x2z1-profile.jpg`)।

## ফাইল ফিল্টারিং, সার্ভার স্ট্যাটিক ডিরেক্টরি এবং এডিট/আপডেট হ্যান্ডলিং

### ১. ব্যাকএন্ড ফাইল ফিল্টারিং (`fileFilter`)

সার্ভারের নিরাপত্তা নিশ্চিত করতে ব্যাকএন্ডেও যাচাই করা দরকার ইউজার সত্যি কোনো ইমেজ পাঠিয়েছে নাকি কোনো ক্ষতিকর এক্সিকিউটেবল ফাইল (`.exe`, `.sh`) পাঠিয়েছে।

```
const fileFilter = (req, file, cb) =&gt; {
  // ফাইল এর MIME Type পরীক্ষা করা
  if (file.mimetype === 'image/png' || file.mimetype === 'image/jpeg' || file.mimetype === 'image/jpg') {
    cb(null, true); // ফাইল গ্রহণ করা হলো
  } else {
    cb(null, false); // ফাইল প্রত্যাখ্যান করা হলো
  }
};

const upload = multer({
  storage: storage,
  fileFilter: fileFilter
});

```

যদি `cb(null, false)` কল হয়, তবে Multer কোনো ফাইল সেভ করে না এবং কন্ট্রোলারে `req.file` মানটি `undefined` থাকে।

### ২. আপলোড করা ছবি ব্রাউজারে প্রদর্শন করা (`express.static`)

সার্ভারে `uploads/a8f9x2z1-pic.jpg` সেভ হলো, কিন্তু ব্রাউজারে `http://localhost:3000/uploads/a8f9x2z1-pic.jpg` দিলে `404 Not Found` দেখায় কেন?

কারণ Express নিরাপত্তা রক্ষার্থে সার্ভারের সব ফোল্ডারকে ডিফল্টভাবে প্রাইভেট রাখে। ফাইলগুলোকে ব্রাউজারে এক্সেসযোগ্য করতে আমাদের সেই ফোল্ডারকে **Static Directory** করতে হয়।

```
// app.js
const path = require('path');

// /uploads রাউটে আসা রিকোয়েস্টগুলোকে সরাসরি লোকাল uploads ফোল্ডারের সাথে কানেক্ট করা
app.use('/uploads', express.static(path.join(__dirname, 'uploads')));

```

### ৩. এডিট/আপডেট ফর্মে ফাইলের লজিক হ্যান্ডলিং

একটি ডাটা এডিট করার সময় ব্যবহারকারী সবসময় ছবি নাও বদলাতে পারেন। কেবল দাম বা নাম আপডেট করতে পারেন।

**ভুল পদ্ধতি:** ইউজার এডিট ফর্মে নতুন ছবি না দিলে নতুন `req.file` থাকবে না (`undefined`) এবং ডাটাবেসে ছবির পাথ শূন্য বা `null` হয়ে আপডেট হয়ে ছবি গায়েব হয়ে যাবে।

**সঠিক লজিক:**

```
exports.postEditHome = async (req, res, next) =&gt; {
  const { homeId, title, price } = req.body;
  const home = await Home.findById(homeId);
  
  home.title = title;
  home.price = price;
  
  // কেবল যদি নতুন ফাইল আপলোড করা হয়, তবেই ছবির পাথ পরিবর্তন হবে
  if (req.file) {
    home.photo = req.file.path;
  }
  
  await home.save();
  res.redirect('/host/homes');
};

```

## অরিজিনাল ফাইল ডিলিট করা (fs.unlink) এবং সিকিউর ফাইল ডাউনলোড (res.download)

### ১. সার্ভার থেকে অব্যবহৃত ফাইল ডিলিট করা (`fs.unlink`)

যখন ইউজার একটি প্রোফাইল পিকচার পরিবর্তন করে নতুন ছবি আপলোড করেন, তখন আগের ছবিটি কিন্তু লোকাল `uploads` ফোল্ডারে রয়ে যায়। এভাবে হাজার হাজার অব্যবহৃত ফাইল জমা হলে সার্ভারের মেমরি নষ্ট হয়।

Node.js-এর বিল্ট-ইন File System (`fs`) মডিউলের `fs.unlink()` মেথড ব্যবহার করে ফাইল মুছে ফেলা যায়:

```
const fs = require('fs');

// কাস্টম হেল্পার ফাংশন
const deleteFile = (filePath) =&gt; {
  fs.unlink(filePath, (err) =&gt; {
    if (err) {
      console.error('ফাইল ডিলিট করতে সমস্যা হয়েছে:', err);
    }
  });
};

// আপডেট লজিকে ব্যবহার:
if (req.file) {
  // ১. পুরানো ফাইলের পাথ ডিলিট করা
  deleteFile(oldHome.photo);
  // ২. নতুন ফাইল অ্যাসাইন করা
  oldHome.photo = req.file.path;
}

```

### ২. সিকিউর বা অথেন্টিকেশন ভিত্তিক ফাইল ডাউনলোড (`res.download`)

কিছু কিছু ফাইল (যেমন: পেমেন্ট রিসিট, ইউজার সার্টিফিকেট, বা কনফিডেনশিয়াল ফাইল) সরাসরি পাবলিক করা অনুচিত। এগুলো কেবল লগইন করা অনুমোদিত ইউজার ডাউনলোড করতে পারবেন।

এর জন্য ফাইলটিকে `express.static`\-এ রাখা যাবে না। একটি সুরক্ষিত কন্ট্রোলার রাউটের ভেতর `res.download()` ব্যবহার করতে হবে:

```
// controller/store.js
const path = require('path');

exports.getHouseRules = (req, res, next) =&gt; {
  // ১. অথেন্টিকেশন চেক (মিডলওয়্যার দ্বারা সমর্থিত)
  if (!req.session.isLoggedIn) {
    return res.redirect('/login');
  }
  
  const filePath = path.join(__dirname, '..', 'data', 'rules.pdf');
  
  // ২. ব্রাউজারে সরাসরি ডাউনলোড স্ট্রিম হিসেবে ফাইল পাঠানো
  res.download(filePath, 'House-Rules.pdf', (err) =&gt; {
    if (err) {
      console.log('ডাউনলোডে সমস্যা হয়েছে:', err);
    }
  });
};

```

## Common Mistakes, Syntaxes, Module Breakdown ও Practice Questions

### ১. গুরুত্বপূর্ণ Methods, Functions ও Properties

* **req.file**: Multer সিঙ্গেল ফাইল পার্স করলে এই অবজেক্টটি তৈরি করে।
  * `req.file.path`: সার্ভারে ফাইল সেভ হওয়ার পুরো ডিরেক্টরি পাথ (যেমন: `uploads/a1b2-pic.jpg`)।
  * `req.file.mimetype`: ফাইলের মিডিয়া টাইপ (যেমন: `image/png`)।
  * `req.file.originalname`: ক্লায়েন্টের কম্পিউটারে ফাইলের মূল নাম।
* **express.static(folderPath)**: কোনো নির্দিষ্ট ফোল্ডারকে পাবলিক করার এক্সপ্রেস মিডলওয়্যার।
* **fs.unlink(filePath, callback)**: সার্ভার স্টোরেজ থেকে সরাসরি নির্দিষ্ট ফাইল মুছে ফেলে।
* **res.download(filePath, customName)**: ক্লায়েন্ট ব্রাউজারে জোরপূর্বক ফাইল ডাউনলোডের পপআপ পাঠায়।

### ২. Modules ও Packages

* **Built-in Modules (ইনস্টল করতে হয় না):** `fs` (ফাইল সিস্টেম অপারেশন), `path` (ডিরেক্টরি ও পাথ সাজানোর জন্য)।
* **Third-Party Package:** `multer` (`npm i multer` দিয়ে ইনস্টল করতে হয় multi-part ডাটা প্রসেস করার জন্য)।

### ৩. সাধারণ ভুল ও সমাধান (Common Mistakes)

1. **এইচটিএমএল ফর্মে** **enctype** **না দেওয়া:** ফর্মে `enctype="multipart/form-data"` না লিখলে `req.file` সবসময় `undefined` আসবে।
2. **HTML** **name** **এবং Multer Field Name মিল না থাকা:** HTML ইনপুট `` হলে ব্যাকএন্ডে অবশ্যই `upload.single('photo')` ব্যবহার করতে হবে। নাম ভুল হলে ছবি আপলোড হবে না।
3. **Windows-এ ISO Date String নাম হিসেবে দেওয়া:** `new Date().toISOString()` দিলে তাতে ক্লোন (`:`) চিহ্ন থাকে, যা Windows OS-এ ফাইল নাম হিসেবে অবৈধ এবং সার্ভার ক্র্যাশ করে। সমাধান হিসেবে `Math.random()` বা `Date.now()` ব্যবহার করুন।
4. **Uploads ফোল্ডার স্ট্যাটিক না করা:** ছবিতে ক্লিক করলে `404` দেখানোর প্রধান কারণ হলো `express.static()` ব্যবহার করে ফোল্ডারটিকে এক্সেস না দেওয়া।

### ৪. অনুশীলনী প্রশ্ন (Self-Assessment)

1. `application/x-www-form-urlencoded` এবং `multipart/form-data`\-এর প্রধান পার্থক্য কী?
2. Multer ব্যবহার করার সময় `dest` এবং `diskStorage`\-এর মধ্যে কোনটি ব্যবহার করা প্রফেশনাল এবং কেন?
3. একজন ব্যবহারকারী একই ফাইল দুইবার আপলোড করলে প্রথম ফাইলটি যেন নষ্ট না হয়, তার সমাধান কী?
4. একজন ইউজার তার প্রোফাইল এডিট করার সময় ছবি পরিবর্তন করলেন না। আপনার ব্যাকএন্ড লজিক কীভাবে আগের ছবিটি ডাটাবেসে ধরে রাখবে?
5. `fs.unlink()` মেথডটির কাজ কী এবং এটি কোথায় ব্যবহার করা উচিত?

## সারসংক্ষেপ ও কুইজ

### মূল সারসংক্ষেপ

Node.js অ্যাপ্লিকেশনে ফাইল আপলোড প্রসেস করার মূল ভিত্তি হলো ক্লায়েন্ট সাইডে `multipart/form-data` ব্যবহার করা এবং ব্যাকএন্ডে `multer` মিডলওয়্যার দিয়ে ডাটা প্রসেস করে লোকাল ডিস্কে কাস্টম ফিল্টারিং ও ইউনিক নামে সেভ করা। ছবির সঠিক ব্যবহারের জন্য `express.static` দিয়ে পাবলিক এক্সেস দেওয়া, ডাটা এডিটের সময় পুরানো ছবির অস্তিত্ব রক্ষা করা এবং ফাইল পরিবর্তনের সময় `fs.unlink` দিয়ে ফিজিক্যাল ফাইল মুছে ফেলা একটি আদর্শ অ্যাপ্লিকেশন তৈরির মূল নিয়ম।

**মূল শিক্ষণীয় পয়েন্টসমূহ:**

* বাইনারি ফাইল পাঠাতে ফর্মে `enctype="multipart/form-data"` আবশ্যিক।
* `multer.diskStorage` ফাইল নাম ও ডিরেক্টরি কাস্টমাইজ করতে সাহায্য করে।
* ওভাররাইটিং এড়াতে ফাইলের নামের সাথে ইউনিক র্যান্ডম প্রিফিক্স যুক্ত করা হয়।
* ফাইল প্রদর্শন করার জন্য `app.use('/uploads', express.static(...))` ব্যবহার করা হয়।
* অকেজো ছবি দূর করতে `fs.unlink()` এবং সুরক্ষিত ডাউনলোডের জন্য `res.download()` ব্যবহার করা হয়।
