Node.js ইনস্টলেশন, IDE ধারণা, REPL এবং প্রথম JS ফাইল এক্সিকিউশন — বিস্তারিত স্টাডি নোট (Lecture 2)

১. এই ক্লাসে কী কী শেখানো হয়েছে? (Class Overview)

সফল ব্যাকএন্ড ডেভেলপার হওয়ার প্রথম ধাপ হলো একটি সঠিক, নির্ভরযোগ্য এবং সুসংগঠিত ডেভেলপমেন্ট এনভায়রনমেন্ট (Development Environment) গড়ে তোলা। KG Coding / প্রশান্ত স্যারের "Node.js Complete Course"-এর ২য় লেকচারে কীভাবে আপনার ব্যবহৃত কম্পিউটারকে ব্যাকএন্ড কোডিংয়ের জন্য সম্পূর্ণরূপে প্রস্তুত করা যায়, তা অত্যন্ত সহজ ও বাস্তবসম্মত উদাহরণের মাধ্যমে শেখানো হয়েছে। এই ক্লাসে শুধুমাত্র সফটওয়্যার ইনস্টলেশন দেখানো হয়নি, বরং ব্রাউজারের সীমানা পেরিয়ে সরাসরি অপারেটিং সিস্টেমে জাভাস্ক্রিপ্ট চালানোর কৌশল এবং তার পেছনের কারিগরি মেকানিজম ব্যাখ্যা করা হয়েছে।

ক্লাসে আলোচিত মূল বিষয়সমূহ:

* IDE (Integrated Development Environment)-এর পরিচয় ও প্রয়োজনীয়তা: সাধারণ টেক্সট এডিটর বা টার্মিনালের সীমাবদ্ধতা দূর করে IDE কীভাবে একজন ডেভেলপারের প্রোডাক্টিভিটি বহুগুণ বাড়িয়ে দেয়।
* Multi-OS (Mac, Windows, Linux) Node.js ও VS Code সেটআপ: বিভিন্ন অপারেটিং সিস্টেম ও প্রসেসর আর্কিটেকচারের (ARM vs x64) ওপর ভিত্তি করে সঠিকভাবে Node.js এবং Visual Studio Code ইনস্টল করার ধাপসমূহ।
* Windows-এ Native C++ Build Tools-এর গুরুত্ব: উইন্ডোজে ইনস্টলেশনের সময় C++ ডিপেন্ডেন্সি, Python এবং Chocolatey কেন স্বয়ংক্রিয়ভাবে ইনস্টল করতে হয় তার কারিগরি কারণ।
* Linux (Ubuntu)-এ NVM (Node Version Manager): NVM-এর সাহায্যে লিনাক্সে Node.js ইনস্টল করা, nvm list remote-এর মাধ্যমে রিমোট ভার্সন দেখা এবং একাধিক নোড ভার্সন সুইচ করার উপায়।
* VS Code-এর প্রয়োজনীয় কনফিগারেশন: Prettier Extension, Word Wrap (Line Wrap) এবং Tab Size (4 থেকে 2-এ পরিবর্তন) সেটআপ।
* Node.js দিয়ে প্রথম JS ফাইল চালনা: VS Code-এর ইন্টিগ্রেটেড টার্মিনাল থেকে node <filename.js> কমান্ডের মাধ্যমে কোড এক্সিকিউশন।
* fs (File System) মডিউল ও ব্যাকএন্ড সক্ষমতা: CommonJS সিনট্যাক্স require('fs') এবং fs.writeFile() ব্যবহার করে হার্ডডিস্কে ফাইল রাইটিং এবং Node.js-এর Asynchronous Non-blocking I/O-এর প্রাথমিক পরিচয়।
* Node.js REPL (Read-Eval-Print Loop): REPL শেলের ৪টি ধাপ, লাইভ কোড টেস্টিং, পরিবর্তনশীল ভ্যারিয়েবলের আচরণ (undefined রিটার্ন মেকানিজম) এবং Volatile Memory-র সীমাবদ্ধতা।

২. টপিক ১: IDE (Integrated Development Environment) এবং Visual Studio Code সেটআপ

Context & Strategic Importance

প্রোডাকশন-লেভেল সফটওয়্যার ডেভেলপমেন্টে কোড লেখার জন্য একটি সাধারণ টেক্সট এডিটর (যেমন: Notepad বা TextEdit) কখনোই যথেষ্ট নয়। কোডিং করার সময় ফাইল ট্র্যাকিং, কোড ডিবাগিং (Debugging), সিনট্যাক্স হাইলাইটিং এবং টার্মিনাল এক্সিকিউশন—এই সবগুলোর জন্য যদি আলাদা আলাদা সফটওয়্যার ব্যবহার করতে হয়, তবে ডেভেলপারের কাজের গতি চরমভাবে ব্যাহত হয়। IDE এই সমস্ত পৃথক টুলগুলোকে একটি একক অ্যাপ্লিকেশন স্যুট (Software Suite)-এ ইন্টিগ্রেট করে কোডিংকে সহজ, দ্রুত এবং এরর-মুক্ত করে তোলে।

What is it? (এটি কী?)

IDE-এর পূর্ণরূপ হলো Integrated Development Environment (সমন্বিত ডেভেলপমেন্ট পরিবেশ)। এটি একটি পূর্ণাঙ্গ অ্যাপ্লিকেশন যা সফটওয়্যার ডেভেলপমেন্টের জন্য প্রয়োজনীয় সকল টুলকে (যেমন: কোড এডিটর, ফাইল এক্সপ্লোরার, ইন্টিগ্রেটেড টার্মিনাল, ডিবাগার, গিট সাপোর্ট) একটি একক ইন্টারফেসে লাইভ যুক্ত করে।

Why is it used? (কেন এটি ব্যবহৃত হয়?)

যদি IDE ব্যবহার না করা হতো, তবে একজন ডেভেলপারকে কোড লেখার জন্য এডিটর, প্রজেক্ট ফাইল দেখার জন্য ফাইল ম্যানেজার, কোড রান করার জন্য আলাদা টার্মিনাল এবং ভুল খোঁজার জন্য আলাদা ডিবাগার ব্যবহার করতে হতো—অর্থাৎ স্ক্রিনে ১০-১২টি আলাদা উইন্ডো খুলে সুইচ করতে হতো। IDE ব্যবহারের সুবিধা:

* উইন্ডো সুইচিংয়ের মানসিক ক্লান্তি দূর হয়।
* কোডিং, এরর ফাইন্ডিং এবং টেস্টিং এক কেন্দ্রীয় হাব (Central Hub) থেকে পরিচালনা করা যায়।
* কোড লেখার প্রসেস অনেক বেশি স্ট্রীমলাইনড (Streamlined) হয় এবং ডেভেলপারের কাজের দক্ষতা (Efficiency) বাড়ে।

How does it work & Main Features (কীভাবে কাজ করে ও প্রধান ফিচারসমূহ)

* Syntax Highlighting: ফাংশন, ভ্যারিয়েবল, স্ট্রিং এবং কিওয়ার্ডসমূহকে ভিন্ন ভিন্ন রঙে প্রদর্শন করে, যা কোডের গঠন সহজে পড়তে সাহায্য করে।
* Auto-completion / IntelliSense: কোড টাইপ করার সময় সম্ভাব্য মেথড বা ভ্যারিয়েবলের স্মার্ট সাজেশন দেয়। ফলে দীর্ঘ সিনট্যাক্স মুখস্থ রাখতে হয় না এবং বানান ভুল হওয়ার ঝুঁকি কমে।
* Unified Workspace & Terminal: ফাইল ম্যানেজার, এডিটর এবং ইন্টিগ্রেটেড টার্মিনাল একই উইন্ডোতে অবস্থান করায় বারবার অ্যাপ পরিবর্তন না করে সরাসরি কমান্ড চালানো যায়।
* Version Control & Debugging: Git সরাসরি যুক্ত থাকায় কোডের পরিবর্তন ট্র্যাকিং সহজ হয় এবং এক্সিকিউশনের পূর্বেই লজিক্যাল এরর হাইলাইট করে ডিবাগিংয়ে সাহায্য করে।

(দ্রষ্টব্য: বিভিন্ন প্রযুক্তির নিজস্ব সেরা IDE রয়েছে; যেমন Java-এর জন্য IntelliJ IDEA, Android-এর জন্য Android Studio, iOS-এর জন্য Xcode এবং JavaScript/Node.js-এর জন্য বিশ্বব্যাপী সবচেয়ে জনপ্রিয় IDE হলো Visual Studio Code বা VS Code।)

Visual Studio Code Specific Settings (ভিএস কোড সেটআপ)

Node.js ডেভেলপমেন্ট সুগম করতে ক্লাসে দেখানো ৩টি গুরুত্বপূর্ণ VS Code সেটআপ:

1. Prettier Extension: এটি একটি কোড ফরম্যাটার। কোড সেভ করার সাথে সাথে প্রজেক্টের ইন্ডেন্টেশন এবং স্পেসিং স্বয়ংক্রিয়ভাবে পরিচ্ছন্ন করে দেয়।
2. Word Wrap (Line Wrap): কোনো লাইনে অতিরিক্ত দীর্ঘ কোড থাকলে তা স্ক্রিনের বাইরে ডানদিকে চলে না গিয়ে স্বয়ংক্রিয়ভাবে নিচের লাইনে ফিট হয়ে যায়। ফলে অস্বস্তিকর হরাইজন্টাল স্ক্রলিং (Horizontal Scrolling) এড়ানো যায়।
3. Tab Size (4 to 2): ইন্ডেন্টেশনের জন্য ডিফল্ট ৪টি স্পেস কমিয়ে ২ করার মাধ্যমে কোডের গঠন অতিরিক্ত ডানে সরে যাওয়া রোধ করে স্ক্রিনের মূল্যবান অংশ বাঁচানো যায়।

Mental Model & Real-life Analogy (মানসিক মডেল ও বাস্তব উদাহরণ)

IDE-কে একটি "আধুনিক সুসজ্জিত কারখানার টুলবক্স বা ওয়ার্কস্টেশন"-এর সাথে তুলনা করা যায়। একজন কারিগরের যদি হাতুড়ি, স্ক্রু-ড্রাইভার, মেজারিং টেপ এবং কাটিং মেশিন আলাদা ঘরে না রেখে একটিমাত্র কাজের টেবিলের হাতের নাগালে সাজানো থাকে, তবে তিনি যেভাবে দ্রুত কাজ করতে পারেন—IDE ঠিক একইভাবে একজন ডেভেলপারের জন্য কোডিং সহজ করে দেয়।

কোডিংয়ের জন্য আইডিই প্রস্তুত হওয়ার পর, জাভাস্ক্রিপ্ট কোডকে প্রসেসরে চালানোর জন্য রানটাইম এনভায়রনমেন্ট হিসেবে Node.js ইনস্টল করা প্রয়োজন।

৩. টপিক ২: Multi-OS Node.js ইনস্টলেশন ও এনভায়রনমেন্ট সেটআপ (Mac, Windows, Linux)

Context & Strategic Importance

প্রথাগতভাবে জাভাস্ক্রিপ্ট কেবল ক্লায়েন্ট-সাইড ব্রাউজারে রান করতে পারত। Node.js তৈরি হওয়ার ফলে ব্রাউজারের বাইরে সরাসরি যেকোনো অপারেটিং সিস্টেমে (Mac, Windows, Linux) জাভাস্ক্রিপ্ট চালানো সম্ভব হয়েছে। এটি Google Chrome-এর V8 엔진-এর ওপর ভিত্তি করে নির্মিত। V8 মূলত C++ এ লেখা একটি হাই-পারফর্ম্যান্স ইঞ্জিন, যা জাভাস্ক্রিপ্ট কোডকে অপারেটিং সিস্টেমের কার্নেল এপিআই (Kernel APIs)-এর সাথে যুক্ত করে সরাসরি প্রসেসরের বোধগম্য মেশিন কোডে (Machine Code) অনুবাদ করে।

What is Node.js Installation doing behind the scenes?

আমরা যখন কোনো কম্পিউটারে Node.js ইনস্টল করি, তখন ব্যাকগ্রাউন্ডে মূলত Chrome V8 ইঞ্জিন এবং Node.js-এর C++ বাইন্ডিংস (C++ Bindings) ইনস্টল হয়। জাভাস্ক্রিপ্টের নিজস্ব কোনো ক্ষমতা নেই সরাসরি পিসির ফাইল সিস্টেম বা নেটওয়ার্ক সকেটের সাথে কথা বলার; Node.js-এর এই C++ বাইন্ডিংসগুলোই জাভাস্ক্রিপ্ট এবং প্রসেসরের সিস্টেম কলের (System Calls) মধ্যে সেতু হিসেবে কাজ করে।

OS-Specific Installation Flow (অপারেটিং সিস্টেম ভিত্তিক ইনস্টলেশন ধাপ)

১. Mac Setup (ম্যাক সেটআপ)

* ডাউনলোড: ব্রাউজারে nodejs.org এ গিয়ে "Prebuilt Installer" নির্বাচন করতে হবে।
* আর্কিটেকচার নির্বাচন:
  * Apple Silicon (M1/M2/M3 ইত্যাদি M-chip)-এর জন্য ARM (arm64) ডাউনলোড করতে হবে।
  * পুরোনো Intel Processor ভিত্তিক Mac-এর জন্য x64 সিলেক্ট করতে হবে।
* ইনস্টলেশন: ডাউনলোডেড .pkg ফাইলটি ওপেন করে ডিফল্ট ইনস্টলার নির্দেশিকা অনুসরণ করতে হবে। এর মাধ্যমে Node.js-এর সাথে NPM (Node Package Manager) স্বয়ংক্রিয়ভাবে সেটআপ হয়ে যায়।
* VS Code: code.visualstudio.com থেকে জিপ ফাইল নামিয়ে এক্সট্র্যাক্ট করার পর Visual Studio Code.app-কে Mac-এর Applications ফোল্ডারে ড্রাগ-এন্ড-ড্রপ করতে হবে।

২. Windows Setup (উইন্ডোজ সেটআপ)

* ডাউনলোড: nodejs.org থেকে Windows Installer (.msi) ফাইল ডাউনলোড করতে হবে।

Common Mistakes during Installation

1. ভুল প্রসেসর ফাইল ডাউনলোড: Apple Silicon Mac-এ Intel (x64) ফাইল ইনস্টল করলে পারফরম্যান্সের অবনতি ঘটে।

3. C++ Build Tools এড়িয়ে যাওয়া: উইন্ডোজে ইনস্টলেশনের সময় নেটিভ বিল্ড টুলস বাদ দিলে ভবিষ্যতে NPM প্যাকেজ ইনস্টলেশনের সময় সি-কম্পাইলেশন এরর (C++ compilation error) দেখায়।

ইনস্টলেশন যাচাই শেষ হলে, এবার লোকাল প্রজেক্ট ডিরেক্টরিতে জাভাস্ক্রিপ্ট ফাইল বানিয়ে তা প্রসেসরে রান করার সময় এসেছে।

Backend Capabilities Demonstration: The fs Module

Node.js যে ব্যাকএন্ডের সমস্ত কাজ করতে পারে তা প্রমাণের সবচেয়ে সহজ মাধ্যম হলো বিল্ট-ইন fs (File System) মডিউল। এই মডিউলের মাধ্যমে কোড চালিয়ে কম্পিউটারের হার্ডডিস্কে সরাসরি নতুন ফাইল তৈরি বা আপডেট করা যায়।

Detailed Code Breakdown (কোড বিশ্লেষণ)

const fs = require('fs');

fs.writeFile('output.txt', 'Writing file', (err) => {
    if (err) {
        console.log('Error occurred');
    } else {
        console.log('File written');
    }
});


* const fs = require('fs');: Node.js-এর ডিফল্ট CommonJS মডিউল সিস্টেম ব্যবহার করে বিল্ট-ইন fs মডিউলকে বর্তমান ফাইলে লোড বা ইমপোর্ট করা হচ্ছে।
* fs.writeFile(): এটি ফাইলে তথ্য লেখে। এটি মূলত ৩টি ইনপুট প্যারামিটার গ্রহণ করে:
  1. ফাইল নাম/পাথ: 'output.txt' (যে নামে ফাইলটি লোকাল ডিস্কে তৈরি হবে)।
  2. ডেটা: 'Writing file' (ফাইলের ভেতরে সংরক্ষণ করার টেক্সট)।
  3. কলব্যাক ফাংশন (Callback Function): (err) => { ... } (অ্যাসিঙ্ক্রোনাস অপারেশন শেষে নির্বাহ হওয়ার জন্য নির্দেশিত ফাংশন)।

"So What?" Layer: Asynchronous Non-blocking I/O

Node.js-এর সবচেয়ে বড় বৈপ্লবিক দিক হলো এর Non-blocking Asynchronous Execution। হার্ডডিস্কে কোনো ফাইল লেখা বা পড়া একটি ধীরগতির ইনপুট/আউটপুট (I/O) প্রসেস।

যদি fs.writeFile সিঙ্ক্রোনাস (Synchronous) হতো, তবে ফাইল লেখা শেষ না হওয়া পর্যন্ত Node.js-এর মূল সিঙ্গেল থ্রেড (Main Thread) আটকে থাকত এবং পরবর্তী কোড রান করা বন্ধ হয়ে যেত। কিন্তু fs.writeFile অ্যাসিঙ্ক্রোনাস হওয়ায় Node.js ফাইল রাইটিংয়ের এই ভারি কাজটি ব্যাকগ্রাউন্ডে অপারেটিং সিস্টেমের থ্রেড পুলে (OS Thread Pool) পাঠিয়ে দেয় এবং মূল থ্রেড মুক্ত হয়ে অন্য কোড চালাতে থাকে। পরবর্তীতে ফাইল রাইট করা সম্পন্ন হলে কলব্যাক ফাংশনটি (err) => { ... } ট্রিগার হয়।

Practical Impact & Purpose

উপরের কোডটি এক্সিকিউট করলে আপনার ভিএস কোড ফাইল এক্সপ্লোরারে স্বয়ংক্রিয়ভাবে output.txt নামে একটি নতুন ফাইল তৈরি হয়ে যাবে এবং তার ভেতরে Writing file লেখাটি সংরক্ষিত হবে। এটি সরাসরি প্রমাণ করে যে জাভাস্ক্রিপ্ট এখন আর কেবল ব্রাউজারের দৃশ্যমান উপাদানে সীমাবদ্ধ নয়—এটি একটি ব্যাকএন্ড ল্যাঙ্গুয়েজ যা সরাসরি পিসির স্টোরেজ ড্রাইভে ডাটা প্রসেস করতে পারে।

Mental Model

require() মেথডটিকে চিন্তা করুন ওয়ার্কশপের একটি "টুল কেবিনেট" থেকে নির্দিষ্ট সরঞ্জাম (যেমন: ড্রিল মেশিন) বের করে কাজের টেবিলে রাখার মতো, যাতে প্রয়োজন অনুসারে তার মেথডগুলো টেনে ব্যবহার করা যায়।

স্ক্রিপ্ট ফাইলে স্থায়ী কোড লিখে রান করার বিকল্প হিসেবে নোডের একটি দ্রুত ইন্টারঅ্যাক্টিভ প্লেগ্রাউন্ড রয়েছে, যা REPL নামে পরিচিত।

৫. টপিক ৪: Node.js REPL (Read-Eval-Print Loop)

Context & Strategic Importance

প্রজেক্ট ডেভেলপ করার সময় প্রায়ই আমাদের ছোট ছোট কোড বা গাণিতিক লজিক দ্রুত পরীক্ষা করার প্রয়োজন হয়। এর জন্য বারবার একটি নতুন .js ফাইল তৈরি করা, কোড সেভ করা এবং টার্মিনাল থেকে ফাইল চালনা করা একটি ধীরগতির প্রক্রিয়া। এই সমস্যার তাৎক্ষণিক সমাধান প্রদান করে Node.js REPL—যা ব্রাউজার কনসোলের মতোই একটি লাইভ ইন্টারঅ্যাক্টিভ কমান্ড-লাইন এনভায়রনমেন্ট।

What is REPL? (REPL কী?)

REPL হলো একটি রিয়েল-টাইম ইন্টারঅ্যাক্টিভ পরিবেশ। এর পূর্ণরূপ হলো:

* R (Read): ইউজার টার্মিনালে যে জাভাস্ক্রিপ্ট কোড বা ইনপুট টাইপ করে, এটি তা পড়ে।
* E (Eval): V8 ইঞ্জিনের সাহায্যে ইনপুটকৃত কোডটিকে প্রসেস বা ইভালুয়েট (Evaluate) করে।
* P (Print): প্রাপ্ত ফলাফল বা রিটার্ন ভ্যালু তাৎক্ষণিকভাবে টার্মিনালে প্রিন্ট করে দেখায়।
* L (Loop): ফলাফল প্রদর্শনের পর পুনরায় নতুন ইনপুটের জন্য পরবর্তী সাইকেলে ফিরে আসে (Looping)।

How to Use REPL?

১. প্রবেশ করার নিয়ম: কম্পিউটারের যেকোনো টার্মিনালে বা VS Code টার্মিনালে গিয়ে শুধুমাত্র node টাইপ করে Enter চাপুন। ২. ব্যবহারের উদাহরণ:

* গাণিতিক অপারেশন: 4 + 6 লিখে Enter দিলে তাৎক্ষণিক আউটপুট দেখাবে 10
* কনসোল প্রিন্ট: console.log("REPL is really helpful") লিখলে টেক্সটটি ডিসপ্লে করবে।
* ভ্যারিয়েবল অ্যাসাইনমেন্ট ও undefined আচরণ: যখন আপনি টাইপ করবেন let pop = 7 + 9 এবং Enter দেবেন, REPL প্রথম লাইনে প্রিন্ট করবে undefined!

কেন undefined দেখায়? জাভাস্ক্রিপ্টে ভ্যারিয়েবল ডিক্লেয়ারেশন বা অ্যাসাইনমেন্ট স্টেটমেন্ট কোনো মান রিটার্ন করে না। REPL যেহেতু প্রতিটি স্টেটমেন্টের ইভালুয়েটেড রিটার্ন ভ্যালু প্রিন্ট করতে বাধ্য, তাই সে undefined প্রিন্ট করে। এরপরের লাইনে যদি আপনি কেবল ভ্যারিয়েবলের নাম pop লিখে Enter দেন, তবে সে মেমোরি থেকে ইভালুয়েট করে সঠিক মান 16 প্রদর্শন করবে! ৩. প্রস্থান করার নিয়ম: টার্মিনালে পরপর দুইবার Ctrl + C চাপলে বা .exit লিখলে REPL শেল বন্ধ হয়ে যায়।

Characteristics & Limitations of REPL

* Volatile Memory (অস্থায়ী স্মৃতি): REPL যতক্ষণ খোলা থাকে ততক্ষণ ভ্যারিয়েবল ও মেমোরি স্টেট ধরে রাখে। কিন্তু একবার টার্মিনাল বন্ধ করলে বা Ctrl + C চাপলে মেমোরির সমস্ত তথ্য স্থায়ীভাবে মুছে যায়।
* কখন ব্যবহার করবেন: দ্রুত ১-২ লাইনের সিনট্যাক্স টেস্ট, API রেসপন্স মেথড চেক বা লজিক যাচাই করার জন্য।
* কখন ব্যবহার করবেন না: প্রকৃত সফটওয়্যার বা ব্যাকএন্ড প্রজেক্ট ডেভেলপমেন্টে REPL ব্যবহার করা যাবে না; কারণ এর কোড সেভ করা যায় না। প্রজেক্টের জন্য স্থায়ী .js ফাইল আবশ্যক।

Mental Model

REPL হলো একটি "খসড়া স্লেট বা চকবোর্ড"-এর মতো, যেখানে তাৎক্ষণিক হিসেব বা কোড লিখে ফলাফল দেখা যায় এবং মুছে ফেলা যায়। অপরদিকে .js ফাইল হলো একটি "স্থায়ী ডায়েরি" যা ভবিষ্যতে ব্যবহারের জন্য তথ্য নিরাপদে সংরক্ষিত রাখে।

ক্লাসের প্রধান মূল বিষয়গুলোর কারিগরি আলোচনার পর, আসুন ব্যবহৃত মডিউল, সিনট্যাক্স এবং বিভিন্ন কনসেপ্টের তুলনামূলক সারসংক্ষেপ দেখে নেওয়া যাক।

৬. গুরুত্বপূর্ণ মডিউল, প্যাকেজ ও লাইব্রেরি (Modules / Packages / Libraries)

(বিশেষ দ্রষ্টব্য: মনে রাখবেন fs হলো Node.js-এর একটি বিল্ট-ইন কোড মডিউল যা require() দিয়ে ফাইল কোডে ইমপোর্ট করা হয়। অন্যদিকে NPM ও NVM কোনো জাভাস্ক্রিপ্ট মডিউল নয়; এগুলো হলো এক্সটার্নাল কমান্ড-লাইন ম্যানেজমেন্ট টুল বা CLI Tools।)

| নাম | ধরন (Type) | কাজের উদ্দেশ্য | ব্যবহারের স্থান |
| --- | --- | --- | --- |
| fs (File System) | Built-in JavaScript Module | লোকাল ডিস্কে ফাইল তৈরি, পড়া, লেখা ও মুছে ফেলার কাজ করা। | ফাইল ম্যানিপুলেশন সম্পর্কিত ব্যাকএন্ড লজিক তৈরিতে। |
| NPM (Node Package Manager) | Built-in CLI Management Tool | থার্ড-পার্টি লাইব্রেরি ও ডিপেন্ডেন্সি ইনস্টল ও ভার্সন কন্ট্রোল করা। | প্রজেক্টে এক্সটার্নাল প্যাকেজ (যেমন: Express) যুক্ত করতে। |
| NVM (Node Version Manager) | External CLI Version Tool | একই কম্পিউটারে Node.js-এর একাধিক ভার্সন ইনস্টল ও সুইচ করা। | লিনাক্স/ম্যাক ডেভেলপমেন্ট এনভায়রনমেন্ট ম্যানেজমেন্টে। |

৭. গুরুত্বপূর্ণ সিনট্যাক্স ও কিওয়ার্ডস (Important Syntax & Keywords)

1. require('module_name')
  * অর্থ ও উদ্দেশ্য: CommonJS মডিউল সিস্টেমে Node.js-এর বিল্ট-ইন বা ইনস্টলকৃত এক্সটার্নাল কোনো মডিউলকে বর্তমান জাভাস্ক্রিপ্ট ফাইলে লোড বা ইমপোর্ট করার পদ্ধতি।
  * উদাহরণ: const fs = require('fs');
2. node <filename.js>
  * অর্থ ও উদ্দেশ্য: টার্মিনালে বর্তমান ডিরেক্টরিতে থাকা কোনো নির্দিষ্ট জাভাস্ক্রিপ্ট ফাইলকে Node.js রানটাইম ইঞ্জিনের মাধ্যমে এক্সিকিউট করার কমান্ড।
  * উদাহরণ: node first.js
3. Ctrl + C
  * অর্থ ও উদ্দেশ্য: টার্মিনালে রানিং কোনো প্রসেস বাতিল করা অথবা REPL সেশন থেকে বের হওয়া (পরপর দুইবার চাপতে হয়)।

৯. শিক্ষানবিসদের সাধারণ ভুলসমূহ (Common Beginner Mistakes)

* ভুল ১: প্রসেসর আর্কিটেকচার না দেখে ইনস্টলেশন ফাইল নামানো
  * সমস্যা: M-Series চিপের Mac-এ Intel (x64) ইনস্টলার ডাউনলোড করা বা উইন্ডোজের ভুল বিট সিলেক্ট করা।
  * সমাধান: সবসময় পিসির প্রসেসর ইনফরমেশন দেখে Apple Silicon-এর জন্য ARM64 এবং উইন্ডোজের জন্য x64 সঠিকভাবে বেছে নিতে হবে।
* ভুল ২: ভুল ফাইল পাথে থেকে node filename.js কমান্ড চালানো
  * সমস্যা: আপনার ফাইলটি রয়েছে desktop/node-course ফোল্ডারে, কিন্তু টার্মিনাল রয়েছে কেবল desktop-এ। এবার node first.js চালালে দেখাবে Error: Cannot find module '.../first.js'।
  * সমাধান: টার্মিনালে নির্দেশিত ফোল্ডারে নেভিগেট করতে cd <folder-name> কমান্ড ব্যবহার করুন। উদাহরণ: cd node-course, এরপর node first.js চালান।
* ভুল ৩: REPL-এ বড় কোডবেস লিখে তা হারিয়ে ফেলা
  * সমস্যা: নতুন শিক্ষার্থীরা REPL-এ পুরো প্রজেক্টের কোড লিখে ফেলে এবং টার্মিনাল বন্ধ করার পর তা মুছে যায়।
  * সমাধান: প্রজেক্টের লজিক বা কোড সংরক্ষণের জন্য সর্বদা VS Code-এ স্থায়ী .js ফাইল তৈরি করুন।
* ভুল ৪: fs.writeFile-এ কলব্যাক ফাংশন বাদ দেওয়া
  * সমস্যা: fs.writeFile('file.txt', 'data') লিখে রান করলে টাইপেরর (TypeError) বা ওয়ার্নিং দেখায়।
  * সমাধান: অ্যাসিঙ্ক্রোনাস নিয়ম মেনে ৩টি প্যারামিটারই প্রদান করতে হবে: ফাইল নেম, ডেটা, এবং এরর হ্যান্ডলার কলব্যাক (err) => { ... }।

১০. দ্রুত রিভিশন (Quick Revision)

* IDE (VS Code) হলো কোডিংয়ের সেন্ট্রাল হাব, যা ফাইল এডিটর, টার্মিনাল এবং ডিবাগারকে এক ছাদের নিচে এনে কোডিংকে সহজ করে।
* Node.js মূলত V8 ইঞ্জিনের সাহায্যে জাভাস্ক্রিপ্টকে ব্রাউজারের বাইরে সরাসরি যেকোনো ওএস (OS) লেভেলে পরিচালনা করে।
* NVM লিনাক্সে একাধিক নোড ভার্সন সুইচ এবং কন্ট্রোল করার সবচেয়ে নির্ভরযোগ্য CLI টুল।
* node <filename.js> কমান্ড ব্যবহার করে সরাসরি যেকোনো জাভাস্ক্রিপ্ট ফাইল প্রসেসরে রান করা যায়।
* fs (File System) মডিউলের মাধ্যমে জাভাস্ক্রিপ্ট ব্রাউজারের সীমানা পেরিয়ে কম্পিউটারের হার্ডডিস্কে ফাইল রিড/রাইট করতে পারে।
* REPL হলো এক প্রকারের "অস্থায়ী খসড়া স্লেট", যেখানে তাৎক্ষণিক লাইভ কোড লিখে লজিক টেস্ট করা যায়।

১১. গুরুত্বপূর্ণ মেথড ও ফাংশন (Important Methods / Functions)

* console.log(): আউটপুট কনসোলে বা টার্মিনালে ডাটা প্রদর্শন করা।
* require(): Node.js-এর কোনো বিল্ট-ইন বা এক্সটার্নাল মডিউলকে কোড ফাইলে ইমপোর্ট করা।
* fs.writeFile(): সম্পূর্ণ অ্যাসিঙ্ক্রোনাস উপায়ে লোকাল ফাইল সিস্টেমে নতুন তথ্য বা ফাইল রাইট করা।

১২. গুরুত্বপূর্ণ মডিউল ও প্যাকেজ সংক্ষেপ (Important Modules Summary)

* fs (File System): লোকাল ফাইল সিস্টেমে তথ্য সেভ, এডিট ও রিড করার বিল্ট-ইন ব্যাকএন্ড মডিউল।
* NPM (Node Package Manager): জাভাস্ক্রিপ্ট ইকোসিস্টেমের এক্সটার্নাল প্যাকেজ ও ডিরেক্টরি ম্যানেজ করার অফিসিয়াল ম্যানেজমেন্ট টুল।
* NVM (Node Version Manager): লিনাক্সে কমান্ড লাইনের মাধ্যমে একাধিক Node.js ভার্সন ইনস্টল ও ব্যবহারের টুল।

১৩. গুরুত্বপূর্ণ পারিভাষিক শব্দ (Important Terms)

* IDE: কোডিং, প্রজেক্ট ফাইল ট্র্যাকিং এবং ডিবাগিংয়ের সমন্বিত সফটওয়্যার পরিবেশ।
* REPL: রিয়েল-টাইমে কোড পরীক্ষা করার ইন্টারঅ্যাক্টিভ Read-Eval-Print-Loop টার্মিনাল।
* V8 Engine: Google Chrome-এর ওপেন সোর্স ইঞ্জিন, যা জাভাস্ক্রিপ্টকে সি++ বাইন্ডিংয়ের মাধ্যমে প্রসেসরের মেশিন কোডে রূপান্তর করে।
* LTS: লং টার্ম সাপোর্ট সংবলিত অফিসিয়াল সফ্টওয়্যার সংস্করণ, যা দীর্ঘমেয়াদে বাগ-ফিক্স ও সিকিউরিটি আপডেট পায়।

১৪. অবশ্যই মনে রাখার বিষয় (What I Must Remember)

* Node.js মূলত Chrome V8 ইঞ্জিন এবং C++ বাইন্ডিংয়ের সাহায্যে জাভাস্ক্রিপ্টকে অপারেটিং সিস্টেম কার্নেলের সাথে যুক্ত করে।
* স্থায়ী প্রজেক্টের জন্য সবসময় .js ফাইল বানাতে হবে, আর তাৎক্ষণিক ১-২ লাইনের সিনট্যাক্স টেস্টে ব্যবহার করতে হবে REPL।
* উইন্ডোজে Node.js ইনস্টলের সময় C++ Build Tools অপশনে টিক দিতে হয়, কারণ পরবর্তীতে অনেক NPM প্যাকেজ স্থানীয়ভাবে C/C++ বাইনারি কম্পাইল করে।
* fs.writeFile() মেথডটি Non-blocking Asynchronous উপায়ে কাজ করে—এটি ব্যাকগ্রাউন্ডে ফাইল সেভ করে এবং প্রসেস শেষ হলে কলব্যাক ফাংশন নির্বাহ করে।

১৫. অনুশীলনী প্রশ্নাবলী (Practice Questions)

1. IDE কী? সাধারণ টেক্সট এডিটর বাদ দিয়ে ব্যাকএন্ড ডেভেলপমেন্টে IDE ব্যবহারের প্রধান তিনটি কারণ ব্যাখ্যা কর।
2. Node.js ইনস্টলেশনের সময় LTS এবং Current ভার্সনের মধ্যে টেকনিক্যাল পার্থক্য কী? লার্নিং পর্যায়ে কোনটি বেছে নেওয়া উচিত?
3. উইন্ডোজ পিসিতে Node.js ইনস্টলের সময় C++ Build Tools ও Python কেন ইনস্টল করার প্রয়োজন হয়?
4. REPL-এর ৪টি পর্যায় কি কি? REPL-এ let pop = 7 + 9 লিখলে কেন শুরুতে undefined আউটপুট দেখায়?
5. লিনাক্সে nvm list remote কমান্ডটির ভূমিকা কী? লিনাক্সে এনভিএম ব্যবহারের সুবিধা লেখ।
6. ব্রাউজার জাভাস্ক্রিপ্ট ও Node.js-এর কাজের মধ্যে ফাইল সিস্টেম এক্সেসের নিরিখে মূল পার্থক্য বুঝিয়ে লেখ।
7. node app.js কমান্ডটি চালানোর পর যদি Error: Cannot find module বার্তা আসে, তবে সমস্যার মূল কারণ কী এবং তা কীভাবে cd কমান্ড দিয়ে সমাধান করবে?
8. fs.writeFile() মেথডটি কেন Asynchronous বলা হয়? এর প্যারামিটারে থাকা কলব্যাক ফাংশনটির গুরুত্ব কী?
