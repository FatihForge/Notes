Lecture 3: First Node Server, DNS, Protocols, and Core Modules (লেকচার ৩: প্রথম নোড সার্ভার, ডিএনএস, প্রটোকল এবং কোর মডিউল)

১. এই ক্লাসে কী কী শেখানো হয়েছে? (Class Overview)

ওয়েব ডেভেলপমেন্টের শিক্ষাসফরে ক্লায়েন্ট-সাইড টেকনোলজি (যেমন React বা ব্রাউজার UI) থেকে ব্যাকএন্ড আর্কিটেকচারে পদার্পণ করা প্রতিটি ফুল-স্ট্যাক ডেভেলপারের জন্য একটি অত্যন্ত গুরুত্বপূর্ণ কৌশলগত মাইলফলক। এখন পর্যন্ত আমরা মূলত ব্রাউজার লেভেলে কাজ করেছি, যেখানে ইউজার ইন্টারফেস প্রদর্শন এবং ক্লায়েন্ট-সাইড ইন্টারঅ্যাকশনের ওপর আলোকপাত করা হতো। কিন্তু ব্যাকএন্ড ইঞ্জিনিয়ারিংয়ের মূল ভিত্তি হলো নেটওয়ার্ক আর্কিটেকচার বোঝা—কীভাবে একটি ব্যাকএন্ড সার্ভার তৈরি করতে হয়, কীভাবে এটি নেটওয়ার্ক পোর্টে কানেকশনের জন্য কান পেতে (Listen) বসে থাকে এবং কীভাবে নেটওয়ার্কের মাধ্যমে ক্লায়েন্টের পাঠানো অনুরোধ (Request) প্রক্রিয়া করে সঠিক উত্তর (Response) পাঠাতে হয়। প্রশান্ত স্যারের এই লেকচারে আমরা ওয়েব ব্যাকএন্ডের মৌলিক পরিকাঠামো এবং প্রথম Node.js সার্ভার তৈরির বাস্তব প্রয়োগ বিশদভাবে আলোচনা করেছি।

লেকচারের প্রধান আলোচ্য বিষয়সমূহ:

* DNS (Domain Name Service)-এর অভ্যন্তরীণ কার্যপ্রণালী: কীভাবে মানুষের বোধগম্য ডোমেইন নেম কম্পিউটারের জন্য বোধগম্য IP অ্যাড্রেসে রূপান্তরিত হয়।
* Web Request Flow-এর পূর্ণাঙ্গ জীবনচক্র (Lifecycle): একটি ব্রাউজার অনুরোধ তৈরি থেকে শুরু করে সার্ভারে প্রসেসিং এবং পুনরায় ব্রাউজারে UI রেন্ডার হওয়া পর্যন্ত ৮টি ধারাবাহিক ধাপ।
* নেটওয়ার্কিং প্রটোকল (Networking Protocols): HTTP, HTTPS এবং TCP প্রটোকলের কাজ, সংযোগ স্থাপন (Handshake) এবং নিরাপত্তার পার্থক্য।
* Node.js Core Modules ও require কিওয়ার্ড: ফাইল সিস্টেম ও নেটওয়ার্ক অপারেশনের জন্য পূর্ব-নির্ধারিত মডিউল এবং স্ক্রিপ্টে তা অন্তর্ভুক্ত করার পাথ রেজোলিউশন নিয়মাবলী।
* প্রথম Node.js ওয়েব সার্ভার তৈরি: http মডিউল ব্যবহার করে নেটওয়ার্ক পোর্টে লিসেন করা, ইনকামিং req অবজেক্ট বিশ্লেষণ এবং res.end() দিয়ে রেসপন্স সমাপ্ত করা।

ওয়েব আর্কিটেকচারের এই মৌলিক তাত্ত্বিক ভিত্তি জানা অত্যন্ত জরুরি, কারণ সার্ভার-সাইড জাভাস্ক্রিপ্ট কোড লেখার আগে নেটওয়ার্কে ডাটা কীভাবে পরিভ্রমণ করে তা বোঝা একটি স্কেলেবল ও স্থিতিশীল ব্যাকএন্ড তৈরির পূর্বশর্ত।

২. DNS এবং Web কীভাবে কাজ করে? (DNS & Web Architecture)

ওয়েব ডেভেলপমেন্ট শেখার সময় ডেভেলপারের জন্য কেবল URL-কে একটি সাধারণ টেক্সট মনে করা অনুচিত। নেটওয়ার্কিংয়ে ব্রাউজার কীভাবে নির্দিষ্ট ওয়েব সার্ভারকে খুঁজে বের করে এবং IP অ্যাড্রেস কীভাবে কাজ করে, তার অভ্যন্তরীণ প্রক্রিয়া বোঝা অপরিহার্য।

DNS এবং IP Address কী?

* DNS (Domain Name Service / Domain Name Entry): এটি হলো ইন্টারনেট জগতের একটি ঠিকানার খাতা বা বিশ্বব্যাপী বিস্তৃত ফোনবুক (Address Directory)। এটি কোনো ওয়েবসাইটের মানুষের পাঠযোগ্য নামকে (যেমন google.com) কম্পিউটারের ব্যবহারযোগ্য গাণিতিক ঠিকানায় রূপান্তর করে।
* IP Address (Internet Protocol Address): ইন্টারনেটে সংযুক্ত প্রতিটি ডিভাইসের (কম্পিউটার বা সার্ভার) একটি অনন্য গাণিতিক পরিচয় বা নম্বর থাকে, যাকে IP অ্যাড্রেস বলা হয় (যেমন 87.51.200.13)।

কেন DNS ব্যবহার করা হয়?

মানুষের পক্ষে প্রতিটি ওয়েবসাইটের জটিল গাণিতিক IP অ্যাড্রেস (যেমন 87.51.200.13) মনে রাখা অসম্ভব, কিন্তু google.com বা completecoding.in-এর মতো নাম মনে রাখা অত্যন্ত সহজ। তাছাড়া, ব্যাকএন্ডে সার্ভার হার্ডওয়্যার বা লোকেশন পরিবর্তন হলে IP অ্যাড্রেস পরিবর্তিত হতে পারে, কিন্তু ডোমেইন নেম অপরিবর্তিত থাকে। DNS এই পরিবর্তনশীল IP অ্যাড্রেস এবং স্থির ডোমেইন নেমের মধ্যে সঠিক মানচিত্রায়ন (Mapping) বজায় রাখে।

কীভাবে কাজ করে? (Step-by-Step Flow)

নিচে ৮টি ধারাবাহিক ধাপে DNS অনুসন্ধানের পূর্ণাঙ্গ প্রবাহচিত্র দেখানো হলো:

```text
[Client / Browser] ──(1. Query: google.com)──> [DNS Resolver]
                                                     │
                                           (2. Query)│(3. Root TLD Direct)
                                                     ▼
                                            [Root DNS Server]
                                                     │
                                           (4. Query)│(5. TLD Record)
                                                     ▼
                                              [TLD Server]
                                                     │
                                           (6. Query)│(7. Returns IP)
                                                     ▼
                                       [Authoritative DNS Server]
                                                     │
[Client / Browser] <──(8. Direct Connection with IP)─┘
```


১. ইনভোকেশন (Client Query): ব্যবহারকারী ব্রাউজারে ডোমেইন নাম (যেমন google.com) লিখে ইন্টার চাপলে ব্রাউজার প্রথম অনুরোধ পাঠায়।
২. DNS Resolver অনুসন্ধান: অনুরোধটি আপনার ISP (Internet Service Provider)-এর DNS Resolver-এর কাছে পৌঁছায়।
৩. Root DNS Server নির্দেশিকা: Resolver অনুসন্ধানের জন্য Root DNS Server-কে প্রশ্ন করে। Root সার্ভার ডোমেইনের টিএলডি (TLD) এক্সটেনশন অনুযায়ী (যেমন .com, .in, .ai) সঠিক Top Level Domain Server-এর দিকনির্দেশনা দেয়।
৪. TLD Server অনুসন্ধান: Resolver নির্দিষ্ট TLD Server-এ (যেমন .com-এর জন্য Verisign বা .org-এর জন্য PIR পরিচালিত সার্ভার) অনুরোধ পাঠায়।
৫. Authoritative DNS রেফারেন্স: TLD সার্ভার অনুরোধটিকে সংশ্লিষ্ট ডোমেইনের নির্দিষ্ট Authoritative DNS Server-এর দিকে রিডাইরেক্ট করে।
৬. Authoritative DNS সার্ভারে হিট: Resolver সরাসরি Authoritative DNS Server-কে মূল IP অ্যাড্রেসের জন্য অনুসন্ধান করে।
৭. IP ফেরত পাঠানো: Authoritative DNS Server তার রেকর্ড থেকে উক্ত ডোমেইনের সঠিক IP অ্যাড্রেসটি (87.51.200.13) Resolver-কে প্রদান করে, যা পুনরায় ব্রাউজারে ফিরে আসে।
৮. সরাসরি কানেকশন স্থাপন: ব্রাউজার প্রাপ্ত IP অ্যাড্রেস ব্যবহার করে সরাসরি টার্গেট ওয়েব সার্ভারের সাথে টিসিপি কানেকশন তৈরি করে ওয়েব পেজ লোড করে।

কখন ব্যবহার করা হয়?

প্রতিবার যখন কোনো ব্যবহারকারী ব্রাউজারে নতুন URL টাইপ করেন বা কোনো ব্যাকএন্ড API ইনভোক করা হয়, ব্যাকগ্রাউন্ডে এই DNS প্রক্রিয়াটি স্বয়ংক্রিয়ভাবে ঘটে।

মানসিক মডেল ও রূপক (Mental Models & Analogies)

* ডাকঘর ও পিন কোড ব্যবস্থা (Post Office & Pin Code): শহরের নাম হিসেবে "মুজাফ্ফরনগর" এবং "মুজাফ্ফরপুর" ধ্বনিগতভাবে কাছাকাছি হওয়ায় বিভ্রান্তি তৈরি করতে পারে। কিন্তু তাদের নির্ধারিত "পিন কোড" যেমন সঠিক ভৌগোলিক অবস্থান নিশ্চিত করে, তেমনই ডোমেইন নেম সদৃশ হলেও নির্দিষ্ট IP অ্যাড্রেস সার্ভারের সুনির্দিষ্ট অবস্থান নির্দেশ করে।
* পাড়ার নাপিত বা পানওয়ালা (Neighborhood Barber/Panwari): পাড়ার দোকানদার যেমন এলাকার কার বাড়ি কোথায় তা নিখুঁতভাবে বলে দিতে পারে, DNS সার্ভারও ঠিক তেমনি ইন্টারনেটে কোন ডোমেইন নাম কোন IP ঠিকানায় অবস্থিত তার নিখুঁত দিকনির্দেশনা দেয়।

সাধারণ ভুল ধারণা: অনেক শিক্ষানবিস মনে করেন DNS সার্ভার নিজেই ওয়েবসাইটের ফাইল বা কোড হোস্ট করে। প্রকৃতপক্ষে, DNS কেবল একটি ঠিকানার নির্দেশিকা (Directory); এটি কোনো ওয়েবসাইট ফাইল হোস্ট করে না।

DNS সঠিক IP অ্যাড্রেস খুঁজে বের করার পর, ক্লায়েন্ট এবং সার্ভারের মধ্যে ডাটা আদান-প্রদান শুরু হয় নেটওয়ার্কিং প্রটোকলের মাধ্যমে।

৩. Web Request Flow এবং Networking Protocols (HTTP, HTTPS, TCP)

ব্যাকএন্ড ডেভেলপমেন্টে বিভিন্ন কম্পিউটার সিস্টেমের মধ্যে সুশৃঙ্খল, নিরাপদ ও নির্ভুল যোগাযোগ বজায় রাখার জন্য স্ট্যান্ডার্ড নিয়মাবলি বা প্রটোকল (Protocols) ব্যবহার করা হয়।

সম্পূর্ণ Web Request Lifecycle (৮টি নির্দিষ্ট ধাপ)

ধরা যাক, একজন ব্যবহারকারী Myntra-এর ওয়েবসাইটে গিয়ে পুরুষদের জিন্স (myntra.com/mens-jeans) কেনার জন্য অনুরোধ করলেন। এই প্রক্রিয়ার সম্পূর্ণ জীবনচক্রটি নিচে দেওয়া হলো:

১. Client Request Initiation: ব্যবহারকারী ব্রাউজারে ইউআরএল লিখে ইন্টার চাপেন। ২. DNS Resolution: ব্রাউজার DNS সার্ভারের মাধ্যমে myntra.com-এর সঠিক IP অ্যাড্রেস সংগ্রহ করে। ৩. TCP Connection Handshake: ব্রাউজার এবং মাইন্ত্রা সার্ভারের মধ্যে যোগাযোগের জন্য টিসিপি হ্যান্ডশেক সম্পন্ন হয়। ৪. HTTP Request Sending: ব্রাউজার থেকে সার্ভারে নির্দিষ্ট ক্যাটাগরির (Men's Jeans) ডাটা চেয়ে HTTP Request পাঠানো হয়। ৫. Server-side Processing: মাইন্ত্রা সার্ভার অনুরোধটি গ্রহণ করে, প্রসেসিং শুরু করে, ডাটাবেস কোয়েরি করে ১০টি ছবির লিংক, প্রডাক্ট প্রাইজ, ডিসকাউন্ট ও কুপন কোড ডাটাবেস থেকে সংগ্রহ করে। ৬. HTTP Response Generation: সার্ভার সংগৃহীত ডাটা দিয়ে একটি হেডার ও বডিসহ ফাইনাল HTTP Response প্যাকেজ তৈরি করে। ৭. Network Transmission: প্রস্তুতকৃত রেসপন্স ডাটা ডাটা-প্যাকেট আকারে নেটওয়ার্কের মাধ্যমে ক্লায়েন্ট ব্রাউজারে পাঠানো হয়। ৮. Client-side Rendering: ব্রাউজার রেসপন্স ডাটা গ্রহণ করে এইচটিএমএল/সিএসএস/জেএস রান করে একটি সুন্দর ইউজার ইন্টারফেসে (UI) পরিবর্তন করে স্ক্রিনে দেখায়।

নেটওয়ার্কিং প্রটোকলসমূহ

```text
+-------------------------------------------------------------------+
|                     Application Layer: HTTP / HTTPS               |
|  (Plain Text / SSL-TLS Encrypted Data: Requests & Responses)      |
+-------------------------------------------------------------------+
                                  │
                                  ▼
+-------------------------------------------------------------------+
|                     Transport Layer: TCP                          |
|  (Connection Management, Guaranteed Delivery, Ordered Packets)    |
+-------------------------------------------------------------------+
```


TCP (Transmission Control Protocol)

* কাজ: মূল যোগাযোগ শুরুর আগে দুটি কম্পিউটারের মধ্যে নির্ভরযোগ্য নেটওয়ার্ক সংযোগ স্থাপন করা, ডাটা হারানো রোধ করা এবং ডাটা প্যাকেটগুলো সঠিক ক্রমানুসারে পৌঁছানো নিশ্চিত করা।
* রূপক (Phone Call Handshake): ফোনে কথা বলার আগে দুই প্রান্তের মানুষ যেমন "হ্যালো... শুনতে পাচ্ছেন?" বলে কানেকশন পরীক্ষা করে নিশ্চিত হয়, TCP-ও মূল ডাটা পাঠানোর আগে কম্পিউটারের মধ্যে একটি প্রারম্ভিক হ্যান্ডশেক ("SYN, SYN-ACK, ACK") সম্পন্ন করে। কোনো ডাটা প্যাকেট পথে হারিয়ে গেলে TCP তা পুনর্নির্বাচিত করে পাঠায়।

HTTP (HyperText Transfer Protocol)

* কাজ: অ্যাপ্লিকেশন লেয়ারে ক্লায়েন্ট ও সার্ভারের মধ্যে তথ্য আদান-প্রদানের প্রধান প্রটোকল।
* বৈশিষ্ট্য: এটি প্লেন-টেক্সট (Plain-text) আকারে ডাটা আদান-প্রদান করে। এর কোনো নিজস্ব এনক্রিপশন ব্যবস্থা নেই।

HTTPS (HTTP Secure)

* কাজ: HTTP-এর সুরক্ষিত রূপ, যা SSL/TLS (Secure Sockets Layer / Transport Layer Security) এনক্রিপশন লেয়ার ব্যবহার করে।
* প্রয়োজনীয়তা: সাধারণ HTTP প্রটোকলে আপনি পাসওয়ার্ড xyz123 পাঠালে মাঝপথে থাকা যেকোনো ম্যান-ইন-দ্য-মিডল (MITM) হ্যাকার তা সরাসরি পড়ে ফেলতে পারে। HTTPS এই প্লেন-টেক্সটকে একটি জটিল কোডওয়ার্ডে (Encrypted Token) রূপান্তর করে পাঠায়। তাই ই-কমার্স, ব্যাংকিং ও লগইন সিস্টেমে HTTPS ব্যবহার বাধ্যতামূলক।

তাত্ত্বিক নেটওয়ার্কিং প্রটোকল বোঝার পর, এখন আমরা দেখব কীভাবে Node.js তার নিজস্ব বিল্ট-ইন টুল ব্যবহার করে এই ধরনের অনুরোধ হ্যান্ডেল করে।

৪. Node Core Modules এবং require Keyword

Node.js ডেভেলপারদের সুবিধা দেওয়ার জন্য আউট-অফ-দ্য-বক্স বিভিন্ন সিস্টেম ইউটিলিটি প্রদান করে, যাতে নেটওয়ার্কিং বা ফাইল সিস্টেমের মতো মৌলিক ব্যাকএন্ড ইনফ্রাস্ট্রাকচার তৈরির জন্য নতুন করে চাকা আবিষ্কার (Reinvent the wheel) করতে বা থার্ড-পার্টি লাইব্রেরি ইনস্টল করতে না হয়।

Node Core Modules

* কী এটি?: এগুলো হলো Node.js রানটাইম এনভায়রনমেন্ট ইনস্টলেশনের সাথে ডিফল্টভাবে যুক্ত থাকা বিল্ট-ইন মডিউল।
* কেন ব্যবহার করবেন?: এগুলো অত্যন্ত দ্রুতগতির (C++ লেভেলে অপ্টিমাইজড), Node.js কোর টিম কর্তৃক পরীক্ষিত ও শতভাগ বাগ-মুক্ত। এগুলো ব্যবহার করতে কোনো npm install করার প্রয়োজন হয় না।
* মানসিক মডেল (Mental Model): রেস্তোরাঁয় গিয়ে আলাদা অর্ডার দেওয়া ছাড়া ডিফল্ট টেবিলে বিনামূল্যে পাওয়া পানীয় জলের মতো হলো কোর মডিউল। আর স্পেশাল পেইড ডিশ হলো থার্ড-পার্টি প্যাকেজ।
* প্রধান কোর মডিউলসমূহ:
  * http: ক্লায়েন্ট ও সার্ভারের মধ্যে সংযোগ স্থাপন ও ওয়েব সার্ভার তৈরির জন্য।
  * https: এনক্রিপ্টেড ও সিকিউর সংযোগ তৈরির জন্য।
  * fs (File System): সার্ভার হার্ডডিস্কে ফাইল রিড, রাইট বা মডিফাই করার জন্য।
  * path: বিভিন্ন অপারেটিং সিস্টেমের ফাইল ও ডিরেক্টরি পাথ ম্যানেজ করার জন্য।
  * os: অপারেটিং সিস্টেমের মেমোরি, CPU ও ইউজার ইনফরমেশন গ্রহণের জন্য।
  * crypto: ডাটা হ্যাশিং ও সিকিউরিটি ক্রিপ্টোগ্রাফির জন্য।
  * url: ওয়েব URL ভেঙে পার্সিং করার জন্য।

The require Keyword

* কী এটি?: এটি Node.js-এর CommonJS মডিউল সিস্টেমের একটি বিল্ট-ইন ফাংশন, যা কোর মডিউল বা বাহ্যিক ফাইলকে নিজস্ব জাভাস্ক্রিপ্ট ফাইলে ইমপোর্ট (Import) করতে ব্যবহৃত হয়।
* সিনট্যাক্স: const http = require('http');
* অভ্যন্তরীণ কার্যপদ্ধতি: ১. মডিউল কোডটি পড়ে মেমোরিতে লোড করে। ২. পারফরম্যান্স বৃদ্ধির জন্য প্রথমবার ডাকার পর এটি মেমোরিতে ক্যাশে (Cache) রেখে দেয়। ৩. লোকাল ফাইলের ক্ষেত্রে ফাইলের এক্সটেনশন .js না লিখলেও Node তা স্বয়ংক্রিয়ভাবে যুক্ত করে নেয় (যেমন: require('./myModule'))।

পাথ রেজোলিউশন অর্ডার (Path Resolution Order)

\text{Step 1: Core Modules} \longrightarrow \text{Step 2: node\_modules Folder} \longrightarrow \text{Step 3: Relative File Path (./)}

১. Core Modules Check: require('x') লিখলে Node প্রথমে দেখে 'x' কোনো কোর মডিউল (যেমন fs, http) কি না।
২. node_modules Folder Check: কোর মডিউল না হলে প্রজেক্টের node_modules ফোল্ডারে খোঁজে।
৩. Relative File Path Check: আপনি যদি আপেক্ষিক পাথ ./ বা ../ ব্যবহার করেন (যেমন require('./fs')), তখন Node ধাপ ১ ও ধাপ ২ সম্পূর্ণ বাইপাস করে এবং সরাসরি আপনার প্রজেক্টের স্থানীয় ফোল্ডারে ওই নামের ফাইল খোঁজে।

গুরুত্বপূর্ণ নিরাপত্তা টিপ: লোকাল ফাইলের জন্য সামনে ./ না দিলে যদি একই নামে কোনো Core Module থাকে (যেমন fs), তবে Node আপনার লোকাল ফাইল না চালিয়ে Core Module চালিয়ে দেবে (File Shadowing Bug)। তাই লোকাল ফাইলের ক্ষেত্রে ./ ব্যবহার করা বাধ্যতামূলক।

এই কোর মডিউলগুলো ব্যবহার করেই আমরা আমাদের প্রথম কার্যকরী Node.js সার্ভার তৈরি করব।

৫. প্রথম Node.js Server তৈরি করা (Creating the First Node Server)

একটি সাধারণ কম্পিউটারকে নেটওয়ার্ক ক্লায়েন্টের অনুরোধ গ্রহণের উপযোগী একটি সক্রিয় লিসেনিং সার্ভারে রূপান্তর করা ব্যাকএন্ড ইঞ্জিনিয়ারিংয়ের প্রথম বাস্তবসম্মত ধাপ।

সার্ভার তৈরির মূল ধাপসমূহ:

১. http কোর মডিউলটি require করা। ২. http.createServer() ফাংশন কল করে এর ভেতরে একটি Request Listener কলব্যাক ফাংশন পাস করা। ৩. রিকোয়েস্ট লিসেনারে req (IncomingMessage অবজেক্ট) এবং res (ServerResponse অবজেক্ট) প্যারামিটার হিসেবে গ্রহণ করা। ৪. ক্লায়েন্ট ব্যাকগ্রাউন্ডে ঝুলে না থেকে যেন রেসপন্স পায়, সে জন্য res.end() কল করা। ৫. server.listen(PORT, callback) কল করে সার্ভারকে একটি নির্দিষ্ট নেটওয়ার্ক পোর্টে বাইন্ড করা।

সম্পূর্ণ কোড উদাহরণ ও বিশদ ব্যাখ্যা

```javascript
// ১. এইচটিটিপি কোর মডিউল ইমপোর্ট
const http = require('http');

// পোর্ট নম্বর ডিক্লেয়ারেশন (৩০০০ ব্লক থাকলে ৩০০১ ব্যবহার করুন)
const PORT = 3001;

// ২. সার্ভার ইনস্টিংশিয়েশন এবং রিকোয়েস্ট লিসেনার তৈরি
const server = http.createServer((req, res) => {
  // ইনকামিং রিকোয়েস্ট অবজেক্ট টার্মিনালে লগ করা
  console.log(req);

  // ক্লায়েন্টকে রেসপন্স পাঠানো এবং কানেকশন সমাপ্ত করা
  res.end('Hello World from my first Node.js Server!');
});

// ৩. পোর্ট বাইন্ডিং ও ইভেন্ট লুপে সার্ভার চালু রাখা
server.listen(PORT, () => {
  console.log(`Server running on address http://localhost:${PORT}`);
});
```


কোড উপাদানের গভীর বিশ্লেষণ:

* http.createServer(): এটি একটি নতুন Node.js HTTP Server অবজেক্ট তৈরি করে।
* console.log(req) কেন শত শত লাইন আউটপুট দেয়?: শিক্ষানবিসরা console.log(req) দিলে টার্মিনালে বিশাল আউটপুট দেখে ঘাবড়ে যান। মনে রাখতে হবে, req কোনো সাধারণ JSON অবজেক্ট নয়; এটি Node.js-এর একটি জটিল IncomingMessage ক্লাসের ইন্সট্যান্স। এর মধ্যে নেটওয়ার্ক সকেটের তথ্য (socket), রিকোয়েস্ট হেডার্স (rawHeaders), HTTP ভার্সন, মেথড (GET/POST), URL, ব্রাউজার ক্লায়েন্ট ডিটেইলস (User-Agent) সহ নেটওয়ার্ক লেয়ারের শত শত মেটাডাটা থাকে।
* res.end() কেন অপরিহার্য?: HTTP হলো একটি Request-Response সাইকেল। ব্রাউজার অনুরোধ জানানোর পর সার্ভার থেকে তথ্য না পাওয়া পর্যন্ত বা কানেকশন শেষ না হওয়া পর্যন্ত ব্রাউজার লোডিং স্পিনার ঘোরাতে থাকবে (Hanging State)। res.end() মেথড ব্রাউজারকে সংকেত দেয় যে সার্ভারের ডাটা পাঠানো শেষ হয়েছে এবং ট্রান্সমিশন সমাপ্ত হয়েছে।
* server.listen() এবং Event Loop: সাধারণ জাভাস্ক্রিপ্ট কোড এক্সিকিউশন শেষ হওয়ার সাথে সাথে প্রসেস বন্ধ হয়ে যায়। কিন্তু server.listen() একটি ওপেন TCP সকেট লিসেনার রেজিস্টার করে। এটি Node.js-এর ইভেন্ট লুপকে (Event Loop) একটি অসীম অপেক্ষমান অবস্থায় সচল রাখে, যার ফলে ফাইলটি এক্সিকিউট হয়ে বন্ধ হয়ে যায় না; বরং নেটওয়ার্ক পোর্টে ইনকামিং ট্রাফিকের জন্য কান পেতে বসে থাকে।
* পোর্ট ও এড্রেস (Ports & Addresses):
  * localhost / 127.0.0.1: এটি স্থানীয় মেশিনের লুপব্যাক আইপি (Loopback IP Address)। এর মাধ্যমে ক্লায়েন্ট অনুরোধ ইন্টারনেটে না গিয়ে নিজস্ব মেশিনের প্রসেসকে হিট করে।
  * Port Numbers (যেমন: 3000, 3001): একটি কম্পিউটারের ভার্চুয়াল দরজার মতো। একাধিক অ্যাপ একই মেশিনে থাকলে আলাদা পোর্টে চলে।
  * সার্ভার বন্ধ ও রিস্টার্ট: টার্মিনালে Ctrl + C চেপে প্রসেস কিল করতে হয়। ব্যাকএন্ড কোডে কোনো পরিবর্তন করলে সার্ভার Ctrl + C দিয়ে বন্ধ করে পুনরায় node app.js চালিয়ে চালুকৃত সার্ভারে নতুন কোড লোড করতে হয়।

| --- | --- | --- |

| https | Built-in Core | SSL/TLS এনক্রিপ্টেড ও সিকিউর ওয়েব সার্ভার ও ক্লায়েন্ট কানেকশন তৈরি করে। |
| fs | Built-in Core | ফাইল সিস্টেমের সাথে যোগাযোগ করে ফাইল রিড, রাইট, অ্যাপেন্ড বা ডিলিট করে। |
| path | Built-in Core | বিভিন্ন অপারেটিং সিস্টেমে (Mac/Windows/Linux) ফাইল ও ডিরেক্টরি পাথ পার্স ও যোগ করে। |
| os | Built-in Core | অপারেটিং সিস্টেমের মেমোরি, CPU আর্কিটেকচার ও সিস্টেম আপটাইম সম্পর্কিত ডাটা দেয়। |
| crypto | Built-in Core | ডাটা এনক্রিপশন, সাইফার, ডিসাইফার এবং কাস্টম হ্যাশিং তৈরির কাজে লাগে। |
| url | Built-in Core | ওয়েব URL ভেঙে ডোমেইন, পোর্ট, পাথ এবং কোয়েরি প্যারামিটার পার্স করে। |

৭. Important Syntax & Keywords

* require('module_name'): Node.js-এ বিল্ট-ইন বা এক্সটার্নাল মডিউলকে ইমপোর্ট করার কমনজেএস (CommonJS) সিনট্যাক্স।
* http.createServer(callback): একটি নতুন HTTP সার্ভার ইনস্ট্যান্স তৈরি করে এবং প্রতি ইনকামিং রিকোয়েস্টে এক্সিকিউট হওয়ার জন্য রিকোয়েস্ট লিসেনার কলব্যাক রেজিস্টার করে।
* server.listen(port, callback): নির্দিষ্ট নেটওয়ার্ক পোর্টে পোর্ট বাইন্ড করে ইভেন্ট লুপ চালু রাখে যেন সার্ভার ইনকামিং রিকোয়েস্ট শুনতে পারে।
* req (IncomingMessage): ক্লায়েন্ট থেকে আসা ইনকামিং রিকোয়েস্টের হেডার, মেথড, ইউআরএল ও ডাটা স্ট্রিম ধারণকারী অবজেক্ট।
* res (ServerResponse): প্রসেসিং শেষে ক্লায়েন্টে স্ট্যাটাস কোড, হেডার ও ডাটা রেসপন্স পাঠাতে ব্যবহৃত আউটগোয়িং অবজেক্ট।
* localhost / 127.0.0.1: নেটওয়ার্ক ট্রাফিক বাইরে না পাঠিয়ে নিজস্ব মেশিনের লোকাল ইন্টারফেসে ঘুরিয়ে দেওয়ার লুপব্যাক নেটওয়ার্ক আইপি।

৮. Important Differences (তুলনামূলক পার্থক্য)

১. HTTP vs HTTPS

| বৈশিষ্ট্য | HTTP | HTTPS |
| --- | --- | --- |
| এনক্রিপশন | কোনো এনক্রিপশন থাকে না (Plain text transmission)। | SSL/TLS প্রটোকল দ্বারা সম্পূর্ণ এনক্রিপ্টেড ডাটা। |
| নিরাপত্তা | কম সুরক্ষিত, মাঝপথে হ্যাকার ডাটা ইন্টারসেপ্ট করতে পারে। | অত্যন্ত সুরক্ষিত, মাঝপথে ডাটা চুরি বা পরিবর্তন অসম্ভব। |
| ডিফল্ট পোর্ট | ডিফল্টভাবে পোর্ট ৮০ (Port 80) ব্যবহার করে। | ডিফল্টভাবে পোর্ট ৪৪৩ (Port 443) ব্যবহার করে। |
| ব্যবহারের ক্ষেত্র | লোকাল ডেভেলপমেন্ট বা নন-সংবেদনশীল ডাটা। | ই-কমার্স, অনলাইন ব্যাংকিং, পাসওয়ার্ড ও ক্রেডিট কার্ড ফর্ম। |

২. Core Modules vs Local Modules

| বৈশিষ্ট্য | Core Modules | Local Modules |
| --- | --- | --- |
| উৎপত্তি | Node.js ইন্সটলেশনের সাথে ডিফল্টভাবে বান্ডল হয়ে আসে। | ডেভেলপার নিজে প্রজেক্ট ফাইল হিসেবে তৈরি করে। |
| ইনস্টলেশন | কোনো npm install প্রয়োজন নেই। | কোনো ইনস্টলেশন লাগে না, স্থানীয় ফাইল তৈরি করতে হয়। |
| Require সিনট্যাক্স | সরাসরি মডিউলের নাম: require('fs') | আপেক্ষিক পাথ দিতে হয়: require('./myFile') |
| পাথ রেজোলিউশন | Node রানটাইমের অভ্যন্তরীণ বাইনারি মডিউলে খোঁজে। | ./ ব্যবহার করলে ধাপ ১ ও ২ বাইপাস করে সরাসরি ফোল্ডারে খোঁজে। |

৩. IP Address vs Domain Name

| বৈশিষ্ট্য | IP Address | Domain Name |
| --- | --- | --- |
| ফরম্যাট | সংখ্যার বিন্যাস (যেমন: 87.51.200.13 বা IPv6)। | অক্ষরের বিন্যাস (যেমন: google.com)। |
| মানুষের পাঠযোগ্যতা | মানুষের পক্ষে মুখস্থ রাখা কঠিন। | সহজ ও স্মরণযোগ্য। |
| পরিবর্তনশীলতা | ব্যাকএন্ড সার্ভার বা হোস্ট পরিবর্তনের সাথে পরিবর্তনশীল। | অপরিবর্তনশীল (IP পরিবর্তন হলেও ডোমেইন একই থাকে)। |

৯. Common Beginner Mistakes (সাধারণ ভুলসমূহ)

১. server.listen() কল করতে ভুলে যাওয়া

* উপসর্গ: কোড রান করলে node app.js কোনো এরর দেখায় না, কিন্তু চালুর সাথে সাথেই প্রোগ্রাম বন্ধ হয়ে টার্মিনাল প্রম্পট ফেরত আসে। ব্রাউজার থেকে কানেক্ট করা যায় না।
* সমাধান: সার্ভার ইনস্ট্যান্স তৈরির পর অবশ্যই server.listen(PORT) ব্যবহার করতে হবে, যেন ইভেন্ট লুপ বন্ধ না হয়ে ব্যাকগ্রাউন্ডে কান পেতে লিসেন করতে থাকে।

২. Port Collision বা EADDRINUSE এরর

* উপসর্গ: টার্মিনালে Error: listen EADDRINUSE: address already in use :::3000 মেসেজ লাল রঙে ভেসে ওঠে।
* সমাধান: এর অর্থ হলো আপনার কাঙ্ক্ষিত পোর্টে (যেমন 3000) অন্য কোনো ব্যাকগ্রাউন্ড প্রসেস বা অন্য সার্ভার লিসেন করছে। আপনার কোডে পোর্ট সংখ্যা পরিবর্তন করে ৩০০০-এর বদলে ৩০০১ দিন অথবা টার্মিনাল থেকে পুরানো প্রসেসটি বন্ধ (Kill) করুন।

৩. কোড পরিবর্তনের পর নোড সার্ভার ম্যানুয়ালি রিস্টার্ট না করা

* উপসর্গ: app.js ফাইলে নতুন কোনো রেসপন্স বা লজিক লেখার পরও ব্রাউজারে রিলোড দিলে পুরানো আউটপুটই দেখা যায়।
* সমাধান: মূল Node.js রানটাইম স্বয়ংক্রিয়ভাবে ব্যাকএন্ড ফাইলের কোড পরিবর্তন ক্যাচ করতে পারে না। টার্মিনালে Ctrl + C চেপে চলতি প্রসেস বন্ধ করে পুনরায় node app.js চালিয়ে সার্ভার রিস্টার্ট করতে হয়।

৪. লোকাল ফাইল ইমপোর্টে আপেক্ষিক পাথ (./) বাদ দেওয়া

* উপসর্গ: নিজস্ব ফাইল ইমপোর্ট করতে গিয়ে Error: Cannot find module 'myFile' দেখা যায়।
* সমাধান: কাস্টম লোকাল ফাইলের ক্ষেত্রে অবশ্যই সামনে ./ বা ../ ব্যবহার করতে হবে (যেমন: require('./myFile'))। তা না হলে Node তাকে Core Module বা node_modules-এ খুঁজতে গিয়ে ব্যর্থ হবে।

১০. Quick Revision (দ্রুত রিভিশন)

* DNS মানুষের পাঠযোগ্য ডোমেইন নামকে কম্পিউটারের আইপি (IP) ঠিকানায় অনুবাদ করার গ্লোবাল ফোনবুক।
* Web Request Flow ৮টি ধারাবাহিক ধাপে সম্পন্ন হয়: Client Request \rightarrow DNS Resolution \rightarrow TCP Handshake \rightarrow HTTP Request \rightarrow Server Processing \rightarrow HTTP Response \rightarrow Network Transmission \rightarrow Client Rendering।
* TCP প্যাকেট ডেলিভারি ও সংযোগের নিশ্চয়তা দেয়; HTTP অ্যাপ্লিকেশন লেয়ারে ডাটা স্থানান্তর করে এবং HTTPS ডাটা সম্পূর্ণ এনক্রিপ্ট করে সুরক্ষিত রাখে।
* Core Modules Node.js-এর সাথে ডিফল্টভাবে আসে (যেমন: http, fs, path), কোনো ইনস্টলেশন ছাড়াই require() দিয়ে ব্যবহার করা যায়।
* require() প্রথম ডাকার পর মেমোরিতে মডিউল ক্যাশে রাখে এবং এক্সটেনশন না দিলে স্বয়ংক্রিয়ভাবে .js চিনে নেয়।
* http.createServer() দিয়ে সার্ভার তৈরি হয় এবং server.listen() পোর্টে সকেট খোলা রেখে প্রসেস সচল রাখে।
* req হলো একটি বৃহৎ IncomingMessage অবজেক্ট এবং res.end() ডাকা বাধ্যতামূলক যেন ব্রাউজারে লোডিং স্পিনার ঝুলে না থাকে।

১১. What I Must Remember (অবশ্যই মনে রাখতে হবে)

১. ইভেন্ট লুপ ও সার্ভার প্রসেস: server.listen() না ডাকা পর্যন্ত Node.js প্রসেস জীবন্ত থাকে না। ব্যাকএন্ড সার্ভার হলো একটি অসীম সময়ের জন্য কান পেতে থাকা লিসেনার। ২. নিরাপত্তায় HTTPS আবশ্যক: যেকোনো সংবেদনশীল তথ্য বা ব্যাংকিং ডাটা আদান-প্রদানে HTTP-এর বদলে সবসময় HTTPS ব্যবহার বাধ্যতামূলক, নতুবা পাসওয়ার্ড বা সেনসিটিভ ডাটা হ্যাক হওয়ার ঝুঁকি থাকে। ৩. পাথ রেজোলিউশন নিয়ম: require('fs') কোর মডিউল খুঁজবে, কিন্তু require('./fs') বর্তমান ফোল্ডারে থাকা লোকাল ফাইলকে খুঁজবে। লোকাল ফাইল ইমপোর্টে ./ বাদ দিলে ফাইল শ্যাডোয়িং বাগ তৈরি হয়। ৪. ম্যানুয়াল রিস্টার্টের সত্যতা: নোড ইঞ্জিন ডিফল্টভাবে ব্যাকএন্ড ফাইলের কোড পরিবর্তন রিয়েল-টাইমে ক্যাচ করে না; প্রতিবার সার্ভার ম্যানুয়ালি বন্ধ (Ctrl + C) করে পুনরায় সচল করতে হয়। ৫. রেসপন্স সমাপ্তি: রিকোয়েস্ট লিসেনার কলব্যাকে res.end() না ডাকলে ক্লায়েন্ট ব্রাউজার অনির্দিষ্টকালের জন্য হ্যাং হয়ে থাকবে।

১২. Practice Questions (অনুশীলন প্রশ্নাবলী)

১. ডোমেইন নেম সার্ভিস (DNS) কীভাবে কাজ করে এবং কেবল IP অ্যাড্রেস সরাসরি ব্যবহার না করে ডোমেইন নেমের প্রয়োজনীয়তা কী? ২. একটি ওয়েবসাইট অনুরোধ প্রক্রিয়ায় Root DNS Server, TLD Server এবং Authoritative DNS Server-এর ভূমিকা সংক্ষেপে ব্যাখ্যা করুন। ৩. TCP সংযোগে হ্যান্ডশেক (Handshake) বলতে কী বোঝায়? বাস্তব জীবনের সাধারণ ফোনালাপের সাথে এর তুলনা কীভাবে করা যায়? ৪. HTTP এবং HTTPS প্রটোকলের মধ্যে মৌলিক পার্থক্যগুলো কী কী? কেন ব্যাংকিং বা ই-কমার্স সাইটে HTTPS ব্যবহার করা বাধ্যতামূলক? ৫. Node.js-এর "Core Modules" বলতে কী বোঝায়? এগুলো ব্যবহারের সুবিধা কী? ৬. require() কিওয়ার্ড কীভাবে কাজ করে এবং নোড মডিউল খোঁজার ক্ষেত্রে এটি কোন ক্রম (Path Resolution Order) অনুসরণ করে? ৭. require('fs') এবং require('./fs')-এর মধ্যে পার্থক্য কী? ভুল পাথ দিলে কী ধরনের বাগ হতে পারে? ৮. http.createServer() ফাইলে কল করার পর server.listen() ব্যবহার না করলে এবং res.end() না ডাকলে পৃথকভাবে কী কী সমস্যা ঘটবে? ৯. টার্মিনালে EADDRINUSE এররটি কেন আসে এবং কীভাবে এটি সমাধান করা যায়?
